Learn Microsoft Power Platform & Power BI, from zero.

Twenty days, and one project you keep building the whole way through. Everything in your web browser — no software to install, nothing that needs a powerful laptop. Each day explains the why in plain English and the how click-by-click, with diagrams. How to use this course

Do one day at a time. A "day" is roughly 60–120 minutes — split it across a morning and evening if you like. You don't have to finish in 20 calendar days; the number just means there are 20 lessons, grouped into six phases (use the menu on the left).

The kinds of boxes you'll see
  • Concept (blue) — the idea explained simply, then a little more technically, often with a diagram.
  • Do this (green) — the exact clicks, with checkboxes that remember your progress.
  • Tip (yellow) — something handy or a shortcut.
  • Careful (red) — something that could cost money or cause a mistake. Read these.
  • Words you learned (purple) — a mini-dictionary for the day.
  • Check yourself (teal) — a tiny quiz to confirm it stuck.
Tip — your progress is saved When you tick a checkbox, this page remembers it on this computer and browser (even after you close it). The bar in the top-left fills as you go. Progress is saved per page, so each phase keeps its own ticks. A different computer won't have your ticks — that's normal.
Careful — two golden rules for the whole course
  1. Only ever use made-up ("fake") data. Names, emails, numbers — invent them all. Never type in real personal or work information from anyone.
  2. Only build in your dedicated learning environment (set up on Day 0). If you used the Power Apps Developer Plan, your environment is named after you — e.g. "Ashwini Pandey's Environment". If an admin created it for you, it may be called "Learning". Either way, always confirm the environment picker (top-right) shows the right one before building anything.

Your project: the Community Library

This course is not a set of unrelated exercises. From Day 2 onward you build one real thing — a Community Library — and it grows a little every day. By the end it's a complete, connected ecosystem: a database, apps people use, automations that run by themselves, a chatbot, and a Power BI report — all sharing the same data. It becomes a project that is genuinely yours, and something you can show people.

Sample data — download before you start

All the realistic data you need for every day of the course is ready-made. Download these files once, keep them somewhere easy to find, and you'll always have data to import, analyse, and practise with.

Download all 9 files — and open each one correctly

Right-click any link below → Save link as → save to a folder called CommunityLibrary on your Desktop. Follow the "How to open" steps under each file so Excel does not mangle dates or numbers.

📥 books.csv — 50 real books: title, author, ISBN, genre, pages, year, rating, copies. Used on Day 2.

  1. Open Excel → click the Data tab → Get Data → From Text/CSV → select books.csv → click Import.
  2. A preview window opens. Click Transform Data (do not click Load yet).
  3. In the Power Query editor, click the ISBN column header to select it.
  4. Go to the Transform tab → click Data Type → choose Text. Click Replace current when asked.
  5. Click Close & Load (top-left). Excel loads all 50 rows with ISBN shown correctly.

📥 authors.csv — 46 real authors: full name, country, birth date, biography. Used on Day 3.

  1. Excel → Data → Get Data → From Text/CSV → select authors.csv → Import.
  2. Click Transform Data.
  3. Click the Born column → Transform → Data Type → Date → Replace current.
  4. Close & Load.

📥 members.csv — 30 library members: name, email, phone, membership type, join date, expiry, active. Used on Day 3.

  1. Excel → Data → Get Data → From Text/CSV → select members.csv → Import.
  2. Click Transform Data.
  3. Click the Phone column → Transform → Data Type → Text → Replace current. (Phone numbers start with + so must be text.)
  4. Click the Join_date column → Data Type → Date → Replace current.
  5. Click the Membership_expiry column → Data Type → Date → Replace current.
  6. Close & Load.

📥 new-members.csv — 15 new members for bulk import. Used on Day 13 (Dataflow).

  1. Excel → Data → Get Data → From Text/CSV → select new-members.csv → Import.
  2. Click Transform Data.
  3. Click Phone → Data Type → Text → Replace current.
  4. Click Join_date → Data Type → Date → Replace current.
  5. Click Membership_expiry → Data Type → Date → Replace current.
  6. Close & Load. (This file is also uploaded directly into the Dataverse Dataflow on Day 13 — you don't have to open it in Excel at all, but it helps to check the data first.)

📥 loans.csv — 100 loan records (Jan 2025–Aug 2026): book, member, dates, status, late fees. Used on Day 17 (Power BI).

  1. Excel → Data → Get Data → From Text/CSV → select loans.csv → Import.
  2. Click Transform Data.
  3. Click Loan_date → Transform → Data Type → Date → Replace current.
  4. Click Due_date → Data Type → Date → Replace current.
  5. Click Return_date → Data Type → Date → Replace current. (Some rows are blank here — that is correct, it means the book has not been returned yet.)
  6. Click Late_fee → Data Type → Decimal Number → Replace current.
  7. Close & Load.

📥 library-events.csv — 20 community events: name, date, location, capacity, description. Used on Day 12 (SharePoint).

  1. Excel → Data → Get Data → From Text/CSV → select library-events.csv → Import.
  2. Click Transform Data.
  3. Click Event_date → Data Type → Date → Replace current.
  4. Close & Load. (You will type these events into the SharePoint list manually on Day 12 — open this file in Excel just to read the data row by row as you type.)

📥 library-faq.txt — 60+ Q&A for the Copilot Studio chatbot knowledge source. Used on Day 15.
📥 borrowing-policy.txt — Full borrowing policy (10 sections). Used on Day 12 & 15.
📥 late-return-policy.txt — Late return fees, grace periods, disputes. Used on Day 15.

These are plain text files — no Excel needed. On Day 15 you upload them directly to Copilot Studio as knowledge documents. Open them in Notepad any time to read the content.

Why real data makes learning faster

Fake data ("Book 1", "Member A") hides real problems — awkward characters in names, dates that span months, books with 0 copies, members who expired. This dataset has all of that baked in deliberately: books with In_stock = No, members with Active = No, loans that are overdue, late fees that vary. When you import it and something looks wrong, that's the exercise.

  • 50 books across 6 genres — fiction, non-fiction, science, biography, textbook, children — enough variety to test filters and charts.
  • 100 loan records spanning 18 months — enough for time-series charts, overdue counts, and meaningful DAX measures.
  • Policy documents that your Copilot Studio chatbot will actually read and quote from.

Concept — your account, your tenant, and why you have three environments

You have been given a learning account — a Microsoft 365 E5 account created by the course administrator inside a shared tenant (your organisation's space in Microsoft's cloud). Everyone on the same tenant can see each other's environments and share work.

For this course you will create three environments, each playing a different role — just like real enterprise teams work:

  • LM-DEV — your building room. You create and edit everything here during Days 1–15.
  • LM-UAT — your testing room. On Day 16 you deploy a locked copy of your work here and test it as a real user would. Nothing is built here directly.
  • LM-PRD — your production room. The final live system. Deployed to after UAT sign-off on Day 16. Nobody edits anything here directly, ever.

LM stands for Library Manager — the project you will build across all 20 days.

Keep your project forever (read this early)

Important — the trial doesn't last, so plan ahead

The Microsoft 365 trial eventually ends. When it does (or if it's cancelled), the tenant is disabled and later deleted — and the running project (apps, flows, tables, reports) goes with it, because it lives in Microsoft's cloud. The good news: you can preserve everything and even keep it running for free, forever. Two layers:

Layer 1 — back it up to files you own

These files are yours permanently, on your computer:

  • The solution — export My Learning Solution as an unmanaged .zip (Day 16). It contains your tables, apps, and flows.
  • The data — export table rows to Excel/CSV (from each table's grid → Export).
  • The Power BI report — save it as a .pbix file (Power BI Desktop), or download it from the Service.
Layer 2 — keep it running for free (the Developer Plan)

The Power Apps Developer Plan (powerapps.microsoft.com/developerplan) is free forever, no card, no expiry, and includes its own Dataverse environment. You import your exported solution there and the whole project keeps working — canvas app, flows, tables, chatbot, and Power BI (free tier for personal use).

The one catch: the Developer Plan must live on an account that survives the trial — not the learner account created inside the trial tenant. So either sign up for the Developer Plan with a separate personal account, or do the export + import before the trial ends. If in doubt, get a Developer Plan early and build a habit of exporting your solution each week.

In one line The trial's copy won't survive cancellation — but export your solution + data + .pbix, and import into a free Developer Plan, and your Community Library is yours to keep and keep using. Day 16 and Day 20 walk you through it.
