Phase 2 · Days 5–8

Building apps

Turn your Dataverse tables into real, working software. You'll design a hand-crafted canvas app called Library Manager with full browse, edit, and loan screens — then meet the auto-generated model-driven back-office app that runs on the same data.

Day 5

Canvas app foundations: the studio, controls, and the formula bar

~100 minutes

Concept — canvas app vs model-driven app

Power Apps gives you two completely different ways to build an app, and understanding the difference is essential:

  • Canvas app — you design every screen, pixel by pixel, by dragging controls onto a blank canvas. Total creative control. You decide where the title goes, what colour the buttons are, what happens on each tap. Think of it as building a custom mobile app or web form, but without writing front-end code. Better for field workers, customer-facing apps, and tailored experiences.
  • Model-driven app — you point it at your data model (tables, views, forms) and Power Apps auto-generates a professional, fully-featured app. The look is standardised (no pixel control), but you get built-in features: activity timelines, business process flows, command bars, automatic mobile layout, offline capability. Better for back-office data entry and management apps where speed and data depth matter more than custom design.

Both apps read and write the same Dataverse tables. This phase builds one of each over the same data.

Concept — the app studio: every panel explained

When you open a canvas app for editing, you see the Studio. Here is every panel:

  • Tree view (left panel, first icon) — a list of every screen and every control on each screen, in a hierarchy. Click anything here to select it. Always rename controls here — BookGallery not Gallery3.
  • Data panel (left panel, cylinder icon) — where you add and manage data sources (Dataverse tables, SharePoint lists, etc.).
  • Media panel (left panel, image icon) — upload images, audio, or video files used in the app.
  • Canvas (centre) — the visual editing area. Drag controls, resize them, arrange them.
  • Properties pane (right) — when you select a control, its properties appear here: text, colour, font, position, size. You can set values directly in these fields.
  • Formula bar (top, above the canvas) — shows the formula for the selected property of the selected control. Click the property dropdown on the left of the formula bar to switch between properties.
  • Insert menu (top toolbar) — the menu to add new controls: Button, Label, Text input, Gallery, Form, etc.
  • Play ▶ button (top right) — runs a preview of the app in a new window. Press Esc to return to editing.
Do this — create the app and set up screens
  • Go to Solutions → My Learning Solution → New → App → Canvas app. Name = Library Manager. Layout = Tablet. Click Create. The Studio opens.
  • In the Tree view, right-click Screen1 → Rename → type BooksScreen. This will be the main browse screen.
  • Click + New screen (the button at the bottom of the Tree view or from Insert menu) → Blank. Rename it BookFormScreen. Repeat once more → Rename to LoanFormScreen. You now have 3 screens in the tree view.
  • Open the Data panel (cylinder icon). Click Add data. Search for Dataverse. Select it. Search for and add: Books, Authors, Members, Loans. All four tables are now available as data sources throughout the app.
  • Click on BooksScreen in the tree view. Insert a Rectangle (Insert → Rectangle). Set its Width = App.Width, Height = 60, X = 0, Y = 0, Fill = RGBA(47, 111, 237, 1). This is your header bar.
  • Insert a Label. Set Text = "Library Manager", Color = White, Font size = 22, FontWeight = Bold, X = 20, Y = 0, Height = 60. This is the app title in the header.
  • Press Play ▶ to see your header bar. Press Esc to return. Press Ctrl+S to save.
Words you learned today
  • Canvas app — an app you design screen-by-screen by dragging controls; total layout control.
  • Model-driven app — an app auto-generated from your tables; standard look, rich features.
  • Studio — the canvas app editor with Tree view, Canvas, Properties pane, and Formula bar.
  • Screen / control / property — one page / an element on it / a setting on that element.
  • Tree view — the hierarchical list of all screens and controls; always rename controls here.
  • Data source — a Dataverse table (or other service) connected to the app.
Check yourself You have a saved app with 3 screens, a blue header bar, a title label, and all 4 Dataverse tables connected as data sources. The app doesn't show data yet — that's Day 6.
Day 6

BooksScreen: gallery, search, and Power Fx formulas

~110 minutes

Concept — Power Fx: the formula language of canvas apps

Power Fx is the language you type into the formula bar. It looks exactly like Excel formulas — in fact it was designed to feel familiar to anyone who knows Excel. Key ideas:

  • You refer to a control by its name: SearchInput, BookGallery.
  • You get a control's value by name + dot + property: SearchInput.Text = "whatever is typed in the SearchInput box right now".
  • Some properties are events — they run code when something happens. OnSelect runs when a button is clicked. OnVisible runs when a screen is navigated to.
  • Functions are capitalized and work like Excel: If(, Filter(, Search(, Navigate(.
  • Use straight quotes "like this", not curly quotes "like this" — curly quotes cause errors.
Concept — Gallery and how Items works

A Gallery is a scrollable list. Its Items property controls what rows appear. Set Items = Books and it shows all books. Use the Search() function to filter by what the user types.

Inside the gallery, ThisItem refers to "the row this particular gallery card is displaying." So ThisItem.Title means "the Title of the book on this particular card." This is how galleries show different data on each card automatically.

From outside the gallery, BookGallery.Selected means "whichever row the user last clicked on." This is how you pass the selected book to a form screen.

Do this — build BooksScreen: gallery and search
  • Click BooksScreen in the tree view. Go to Insert → Gallery → Vertical gallery. A gallery appears on the canvas — resize it to fill the screen below your header (set Y = 120 or so).
  • In the Tree view, right-click the gallery → Rename → BookGallery.
  • With BookGallery selected, look at the Properties pane on the right. Set Data source = Books. The gallery fills with your 5 book rows immediately.
  • In the Properties pane, set Layout = "Title, subtitle, and body". Now each card shows three lines. Click inside the gallery (double-click to enter the gallery template). Click the Title1 label. In the formula bar, confirm its Text property = ThisItem.Title.
  • Click Subtitle1 inside the gallery. Set its Text = ThisItem.Genre — this shows the choice label (e.g. "Children").
  • Click Body1 inside the gallery. Set its Text = "Pages: " & Text(ThisItem.Pages) — the & joins text, and Text() converts the number to text for joining.
  • Press Esc to exit the gallery template. Now add a Text input for search: Insert → Input → Text input. Position it above the gallery. Rename it to SearchInput. In the Properties pane, set HintText = "Search by title…".
  • Click BookGallery. Change its Items property in the formula bar to:
    Search(Books, SearchInput.Text, "cr_title")
    The string "cr_title" is the logical name of the Title column. To find it: go to Dataverse → Book table → Title column → Advanced options → copy the logical name. If your prefix is learn, it might be "learn_title". Replace accordingly.
  • Add a Button for adding new books: Insert → Button. Rename to NewBookBtn. Set Text = "+ New Book". Set OnSelect = NewForm(BookForm); Navigate(BookFormScreen, ScreenTransition.Fade). (BookForm doesn't exist yet — you'll add it on Day 7. The formula is correct; Power Fx just shows a warning for now.)
  • Select BookGallery. Set its OnSelect property = Navigate(BookFormScreen, ScreenTransition.Fade). Now clicking any book row will navigate to the form screen.
  • Play ▶ — type in the search box and watch the gallery filter in real time. Click a book row — you go to BookFormScreen (blank for now). Press Esc. Save.
Tip — how to find the logical column name Go to make.powerapps.com → Tables → Book → click the Title column → scroll to Advanced options. The Logical name field shows something like cr123_title or learn_title. That exact string (with your prefix) goes inside the quotes in the Search() function. You'll need this for filter expressions in Power Automate too.
Words you learned today
  • Power Fx — the Excel-like formula language of canvas apps.
  • Gallery / Items — a scrollable list of rows / the formula that says which rows to show.
  • ThisItem — "the row displayed on this gallery card"; only valid inside a gallery template.
  • BookGallery.Selected — the row the user last clicked in the gallery; used outside the gallery.
  • Search(table, text, "column") — returns rows where the column contains the text.
  • OnSelect — the event property that runs when a button or gallery row is clicked.
  • Navigate(Screen, Transition) — navigates to another screen.
Check yourself BooksScreen shows all 5 books. Typing in SearchInput filters the list. Clicking a book row navigates to BookFormScreen. That's a real search-and-browse screen — a core UI pattern in almost every business app.
Day 7

BookFormScreen and LoanFormScreen: forms, CRUD, and navigation

~120 minutes

Concept — the Edit Form control and its modes

A Form control is the standard way to display and edit one row from a table. It has three modes:

  • View mode — shows the row read-only. The user can see but not change data.
  • Edit mode — shows the row with editable fields. The user can change values and then save.
  • New mode — all fields are empty and blank, ready for a new row.

Key form functions: SubmitForm(FormName) — saves the row to Dataverse (creates if New mode, updates if Edit mode). NewForm(FormName) — switches to New mode. EditForm(FormName) — switches to Edit mode. ResetForm(FormName) — clears unsaved changes and returns to View mode. The form's Item property says which row it is displaying.

Do this — build BookFormScreen
  • Click BookFormScreen in the tree view. Add the same blue header rectangle (Width = App.Width, Height = 60, Fill = RGBA(47,111,237,1)) and a title Label: Text = "Book Details", Color = White, FontSize = 22, Bold.
  • Insert a Back button: Insert → Icon → Back arrow. Position it in the header at the left. Set its OnSelect = Navigate(BooksScreen, ScreenTransition.Back). Set Color = White.
  • Insert → Forms → Edit form. Resize it to fill most of the screen below the header. In the Tree view, rename it to BookForm.
  • With BookForm selected: in Properties pane, set Data source = Books. Click Edit fields → add all fields: Title, ISBN, Genre, Pages, Published year, Description, Available copies, Total copies, In stock, Author. Remove any fields you don't want.
  • Set BookForm's Item property = BookGallery.Selected. This links the form to whichever book was clicked in the gallery.
  • Set BookForm's DefaultMode = If(IsBlank(BookGallery.Selected), FormMode.New, FormMode.View). When arriving via the New button, BookGallery.Selected is blank, so the form opens in New mode. When clicking an existing row, it opens in View mode.
  • Set BookForm's OnSuccess = Navigate(BooksScreen, ScreenTransition.Fade). After saving, the app returns to the books list automatically.
  • Add an Edit button: Insert → Button, rename to EditBtn. Text = "Edit". OnSelect = EditForm(BookForm).
  • Add a Save button: rename to SaveBtn. Text = "Save". OnSelect = SubmitForm(BookForm). Make it visible only in Edit/New mode: Visible = BookForm.Mode = FormMode.Edit || BookForm.Mode = FormMode.New.
  • Add a Cancel button: rename to CancelBtn. Text = "Cancel". OnSelect = ResetForm(BookForm); Navigate(BooksScreen, ScreenTransition.Fade). Same Visible rule as Save.
  • Add a Delete button: rename to DeleteBtn. Text = "Delete". Fill = RGBA(220,53,69,1). OnSelect = Remove(Books, BookGallery.Selected); Navigate(BooksScreen, ScreenTransition.Fade). Visible = BookForm.Mode = FormMode.View (only show delete button in View mode).
  • Add a Lend button on BookFormScreen: Text = "Lend this book". OnSelect = Navigate(LoanFormScreen, ScreenTransition.Fade). Visible = BookGallery.Selected.In stock = true (only show when book is in stock).
  • Play ▶. Click a book on BooksScreen → see it in BookFormScreen in View mode. Click Edit → fields become editable. Change something → Save → you're back at BooksScreen and the change is saved. Click New Book → form is blank → fill in → Save → new row appears. Test Delete too. Press Esc. Save the app.
Do this — build LoanFormScreen
  • Click LoanFormScreen in the tree view. Add the same blue header (rectangle + Label: Text = "New Loan", Color = White).
  • Add a Back arrow icon: OnSelect = Navigate(BooksScreen, ScreenTransition.Back).
  • Insert → Forms → Edit form. Rename it LoanForm. Data source = Loans.
  • Click Edit fields on LoanForm. Add: Book, Member, Loan date, Due date. Keep it focused — only these four for the lending form.
  • Set LoanForm's DefaultMode = FormMode.New — this screen is always for creating a new loan.
  • In the Book field inside LoanForm: click on the Book field card. Find its DefaultSelectedItems property in the formula bar (click on the Book field card in the form, then look for DefaultSelectedItems in the property dropdown). Set it = [BookGallery.Selected]. This pre-fills the book from the selection. (The brackets [ ] create a single-item table.)
  • Set LoanForm's OnSuccess = Navigate(BooksScreen, ScreenTransition.Fade).
  • Add a Save Loan button: Text = "Save Loan". OnSelect = SubmitForm(LoanForm).
  • Add a Cancel button: Text = "Cancel". OnSelect = ResetForm(LoanForm); Navigate(BooksScreen, ScreenTransition.Fade).
  • Set LoanFormScreen's OnVisible = NewForm(LoanForm). This ensures the form resets to blank every time you navigate to this screen, even if it was used before.
  • Play ▶. Click a book → click "Lend this book" → see the book pre-filled in the loan form → pick a member, add dates → Save Loan. Go back to BooksScreen. Open Library Back Office (in another tab) to confirm the Loan row was created in Dataverse. Press Esc. Save.
Tip — ScreenTransition types Navigate(Screen, ScreenTransition.Fade) — fades out then in. ScreenTransition.Cover — new screen slides over from the right (feels like forward navigation). ScreenTransition.Back — new screen slides in from the left (feels like going back). Use Cover/Back pairs to give users a sense of direction.
Words you learned today
  • Edit form / View / Edit / New mode — the control for one row / read-only / editable / blank-new.
  • Item property — the formula that tells the form which row to display.
  • SubmitForm — saves the current form row to Dataverse (create or update).
  • NewForm / EditForm / ResetForm — switch to New / Edit / View (discarding changes) mode.
  • OnSuccess — runs automatically after a successful SubmitForm.
  • OnVisible — runs every time a screen is navigated to.
  • Remove(table, record) — deletes a row from a Dataverse table.
Check yourself Your app has full CRUD: you can browse books, search, view details, edit, create, delete, and lend a book — all saved to Dataverse. That's a production-quality book management workflow.
Day 8

Library Back Office: model-driven app, views, forms, and business rules

~120 minutes

Concept — what model-driven apps give you for free

Canvas apps give you full control — but you design every button, every screen. Model-driven apps trade that control for speed and built-in features:

  • Auto-generated forms and views — the app reads your table columns and creates the form automatically. Change a column → the form updates.
  • Built-in command bars — New, Save, Delete, Refresh buttons appear automatically. No Power Fx needed.
  • Sub-grids — a related table shown inside a record (e.g. all Loans for a Member inside the Member form).
  • Activity timeline — notes, emails, tasks linked to a record.
  • Business process flows — a guided step-by-step process shown at the top of a record.
  • Always mobile-ready — the layout automatically adapts to phones and tablets.
Concept — site map, views, forms, and business rules
  • Site map — the navigation menu of a model-driven app. You define Groups (sections) and Subareas (links to tables or dashboards). Users see this on the left side of the app.
  • View — a saved, filtered, sorted list of rows for a table. Active Books, Overdue Loans, etc. Users switch between views using a dropdown.
  • Form — the layout for a single record. You arrange fields into sections and tabs. A record can have multiple forms (one for quick entry, one for detailed view).
  • Business rule — "if this, then that" logic attached to a table, written in a visual designer with no code. Runs in model-driven apps, canvas apps, and even the Dataverse data grid — everywhere the data is edited.
Do this — create Library Back Office and configure the site map
  • Go to Solutions → My Learning Solution → New → App → Model-driven app. Name = Library Back Office. Click Create.
  • The App Designer opens. In the left Pages panel, click Add page → Dataverse table. Add all four tables: Book, Author, Member, Loan. Click Add.
  • The site map now lists all four tables. Rearrange them by dragging: Book first, then Loan, then Member, then Author.
  • Click Save → Publish → Play. The app opens. You see a left sidebar with your four tables. Click Book → you see a list of all books. Click any book → the auto-generated form shows all its fields. Try creating a new book from the command bar — faster than the canvas app!
Do this — customise views for every table
  • Back in the App Designer, click Book in the Pages list → click Views. You see "Active Books" and "Inactive Books". Click Active Books to edit it.
  • In the View editor, add columns: Title (already there), Author, Genre, Available copies, In stock. Drag to reorder. Set column widths. Sort by Title ascending. Save and publish.
  • Create a new view: click + New view in the view editor. Name = Books in stock. Add filter: In stock = Yes. Sort by Title ascending. Save and publish.
  • Now do Loan views. Edit Active Loans: add columns Loan name, Book, Member, Loan date, Due date, Status. Sort by Due date ascending.
  • Create Overdue Loans view: filter Status = Overdue, sort by Due date ascending. This is the first thing library staff will open every morning.
  • For Member: edit Active Members to show Full name, Email, Membership, Active. Create view Student Members: filter Membership = Student.
Do this — customise forms with sections and sub-grids
  • In App Designer, click Book → Forms → Main form (Information) to open the Form designer.
  • The form has a default layout. Rearrange fields: drag Title to be full-width at the top (Section with 1 column). Below it, add a new 2-column section: left = Author, right = Genre. Next 2-column section: left = Pages, right = Published year. Full-width section: Description. Final 3-column section: Available copies, Total copies, In stock.
  • Add a new Tab at the top of the form. Name it Loan History. Inside that tab, click + Component → Sub-grid. Table = Loan, Default view = Active Loans. Save and publish. Now when you open a Book record, the Loan History tab shows all loans for that book.
  • Open Member → Forms → Main form. Add a sub-grid for Loans on a "Loan History" tab (same pattern). Save and publish.
Do this — add two business rules to the Loan table
  • In the maker portal: Tables → Loan → Business rules → New business rule. The visual designer opens.
  • First rule — Auto-set Overdue status:
    - Condition: Returned Equals No AND Due date Is before Now.
    - Action (in "If Yes" branch): Set field value → Field = Status, Value = Overdue.
    - Set Scope = All Forms.
    - Save → Activate. (This rule fires whenever a form checks the Loan row. To trigger it on schedule, you'll add an Overdue Check flow in Phase 3.)
  • Second rule — Set return date when returned:
    - Condition: Returned Equals Yes AND Return date Does not contain data.
    - Action: Set field value → Field = Return date, to formula = Now().
    - Scope = All Forms. Save → Activate.
  • Test: open a Loan record in Library Back Office. Set Returned = Yes → Save. The Return date field is automatically set to today. Open an overdue Loan (Due date in the past, Returned = No) → when you save, Status should change to Overdue.
Tip — same data, two completely different apps Both Library Manager (canvas) and Library Back Office (model-driven) read and write the exact same Book, Member, and Loan rows in Dataverse. There is only one copy of the data. If a member borrows a book in Library Manager, it appears immediately in Library Back Office. This "one source of truth" principle is fundamental to enterprise software design.
Words you learned today
  • Model-driven app — an app auto-built from your table design; standardised look, rich built-in features.
  • Site map — the navigation menu of a model-driven app (Groups + Subareas).
  • View — a saved, filtered, sorted list of rows for a table; users switch between them.
  • Form — the field layout for one record; supports sections, tabs, and sub-grids.
  • Sub-grid — a related table shown inside a record (e.g. all Loans for a Member).
  • Business rule — visual if-then logic attached to a table; runs in all apps without code.
Check yourself You have two complete apps over the same data. Can you explain when you'd choose canvas vs model-driven in a real project? (Custom consumer or field app → canvas. Fast internal data management or operations tool → model-driven.) Both exist in the real world — great Power Platform developers use both.
