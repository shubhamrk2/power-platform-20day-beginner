Phase 2 · Days 5–8

Building apps

Now you turn your data into something people can use. You'll build a hand-designed canvas app, learn the Power Fx formula language, connect to data, and then meet the auto-generated model-driven app.

Day 5

Your first app: canvas apps

~100 minutes

Concept — what is an app, and a canvas app?

An app is a set of screens people tap or click to get something done. A canvas app lets you design those screens by dragging things onto a blank canvas — like building a PowerPoint slide, but the things you drag can show data and react to taps.

Technically: a canvas app is a set of screens, each holding controls (buttons, labels, text boxes, galleries). Every control has properties (text, colour, position…) you can set, sometimes with a formula.

Do this — build a one-screen app
  • Open My Learning Solution → New → App → Canvas app. Choose Tablet layout. Name it Library Manager — this is your project's main app; you'll grow it all through Phase 2.
  • Insert a Label; set its Text to My Community Library. Make it big/bold.
  • Insert a Text input and a Button; move them around.
  • Select the button; change its Text to Say hello and its Fill colour.
  • Press Play ▶ to preview; Esc to stop; Ctrl+S to save.
Words you learned today
  • App / canvas app — screens people use / an app you design by dragging controls.
  • Screen / control / property — one page / an element on it / a setting on the element.
  • Studio — the canvas app editor. Play ▶ previews it.
Check yourself A saved app with a title, a text input, and a styled button. It won't do anything yet — that's Day 6.
Day 6

Making things happen: Power Fx formulas

~100 minutes

Concept — Power Fx is "Excel for apps"

In Excel you type =A1+B1 and it calculates. In canvas apps you type Power Fx into a control's property and it reacts. Some properties are events — they run when something happens, like a button's OnSelect (runs when clicked).

Concept — essential functions
  • Notify("text") — pop a message on screen.
  • Set(varName, value) — remember a value in a variable for later.
  • If(condition, thenValue, elseValue) — choose between options.
  • & — glue text: "Hello " & NameInput.Text.
  • Navigate(Screen2) — go to another screen.

Refer to a control's value by name + dot + property: NameInput.Text = "the text typed in the box named NameInput".

Do this — make the button react
  • In Library Manager, rename the text input to NameInput in the tree view.
  • Select the button; in the property dropdown choose OnSelect; type Notify("Hello " & NameInput.Text).
  • Play ▶, type a name, click the button — a greeting appears.
  • Now a variable: set OnSelect to Set(gGreeting, "Hi " & NameInput.Text). Add a Label whose Text = gGreeting. Play again — the label updates on click. Save.
Tip — red squiggles are your friend If Power Fx dislikes a formula it underlines it and explains why — usually a missing bracket or quote. Use straight quotes ", not curly ones.
Words you learned today
  • Power Fx — the Excel-like formula language of canvas apps.
  • Event — a property that runs when something happens (OnSelect).
  • Function / variable — a built-in command / a labelled box that remembers a value.
Check yourself Can you make a button that reads a box and shows it back? Then you've written your first working logic. 🎉
Day 7

Showing and editing data: galleries and forms

~110 minutes

Concept — connecting an app to data

So far the app is decoration. Now we connect it to your Book table so it can show and change real rows. A connection to a table is a data source.

Concept — gallery vs form
  • A gallery shows a list of rows (its Items property says which).
  • A form shows one row to view or edit; you save changes with SubmitForm.

A blue "delegation" warning may appear on a formula — it means some work is best done by the database at large scale. For your tiny practice data it never matters.

Do this — list books, add books, and lend them
  • On the first screen, Insert → Gallery → Vertical; rename it to BookGallery (double-click its name in the tree view); choose the Book table. Set the layout to show Title and Author.
  • Insert → Edit form; rename it to BookForm; Data source = Book; Fields = Title, Author, Pages, Genre, In stock. Add a "New" button with OnSelect = NewForm(BookForm) and a "Save" button with OnSelect = SubmitForm(BookForm). Set the form's Item property = BookGallery.Selected. Play, edit a book, Save.
  • Add a "Lend a book" screen (New screen → blank). This is the heart of the app.
  • On it, Insert → Edit form and rename it to LoanForm (double-click its name in the tree view). Set Data source = Loan; Fields = Book, Member, Loan date, Due date. Add a Submit button with OnSelect = SubmitForm(LoanForm). Set the screen's OnVisible = NewForm(LoanForm) so the form is blank each time.
  • Add a Loans gallery showing the Loan table (Book + Member + Due date). Play → create a loan by picking a Book and a Member — you just lent a book through your own app. Save.
Words you learned today
  • Data source — a table your app is connected to.
  • Gallery / form — a list of rows / an editor for one row.
  • SubmitForm / NewForm / EditForm — save / start-new / edit with a form.
  • Delegation — letting the database do heavy work (matters at large scale).
Check yourself Your app lists books, lets you edit one, and add new ones — a real CRUD app (Create, Read, Update, Delete).
Day 8

The other kind of app: model-driven apps (with views & rules)

~110 minutes · this day covers two topics

Concept — canvas vs model-driven

A canvas app is like designing each screen yourself (total control of the look). A model-driven app is the opposite: you point it at your tables and Microsoft builds a tidy, professional, mobile-friendly app automatically. You design the data; the look comes free. Canvas → custom, pixel-perfect; model-driven → fast, data-heavy business apps.

Concept — views, forms, and business rules
  • A view is a saved, filtered, sorted list (e.g. "Books in stock").
  • A form is the field layout for one row (with sections and tabs).
  • A business rule adds simple "if this, then that" logic to a table with no code — e.g. "If Genre = Textbook, make Pages required" — and it applies in every app.
Do this — build a model-driven app, then shape it
  • My Learning Solution → New → App → Model-driven app = Library Back Office. Add pages for all four tables: Book, Author, Member and Loan. Save → Publish → Play.
  • Explore the auto-generated left menu, grids, and forms. Add a new book here and notice how fast it felt vs the canvas app.
  • In the solution, open Book → Views → New view = In stock; filter In stock = Yes. Save & Publish.
  • Book → Business rules → New: if Genre = Textbook then set Pages as Business Required. Activate.
  • In Library Back Office, try adding a Textbook without Pages — the rule blocks you. Switch to the "In stock" view.
Tip — same data, two apps Both your canvas app and this model-driven app read/write the same Book table. Data lives in Dataverse once; many apps share it. Separating "data" from "app" is a big professional idea.
Words you learned today
  • Model-driven app — an app auto-generated from your tables.
  • Site map / command bar — its navigation menu / the standard New/Save/Delete buttons.
  • View — a saved filtered/sorted list of rows.
  • Business rule — no-code "if/then" logic attached to a table.
Check yourself Two apps over the same data, plus a view and a business rule. Could you say when you'd pick canvas vs model-driven? (Custom look → canvas. Fast, data-first → model-driven.)
