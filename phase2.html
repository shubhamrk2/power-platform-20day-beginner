Canvas App — Building What Users Actually See

~4 hours · make.powerapps.com · Developer Plan environment

Vocabulary — Week 5
Screen
One page in a canvas app — like one page in a book, or one room in a house.
Analogy: Pages in a magazine. The home page shows the cover story. You flip to the next page for the full article. In an app, you navigate between screens the same way.
Example: "The library app has 4 screens: Home (search books), Book Details (one book's info), My Loans (my borrowing history), and Profile (my membership details)."
Gallery
A control that displays a list of items — each item in the list gets the same layout, repeated.
Analogy: A bookshelf. Each shelf slot has the same size and shape. Every book appears in a slot. The slot design is defined once — it applies to all books automatically.
Example: "I created a Gallery connected to the Book table. It shows 50 books — each with a cover image, title, and available copies. I designed the layout once; Power Apps repeated it for all 50 rows."
Control
Any individual element in a canvas app — a button, a text box, an image, a gallery, a date picker.
Analogy: Furniture in a room. A sofa, a table, a lamp — each is a separate piece. A screen is the room; controls are the furniture.
Example: "I have a Text Input control where users type the book title to search. Next to it is a Button control labeled 'Search.'"
Property
A setting that controls how a control looks or behaves — its color, size, text, what data it shows, whether it is visible.
Analogy: Adjusting a desk lamp — you can change the height, the brightness, and the direction. These are properties of the lamp.
Example: "The Borrow Button's 'Visible' property is set to: Available_Copies > 0. So the button only appears when copies are available."
Navigate
Moving the user from one screen to another when they click something.
Analogy: Clicking a link on a website takes you to a new page. Navigate does the same thing inside the app.
Example: "When a user taps a book in the Gallery, the app Navigates to the Book Details screen and passes that specific book's data so the screen shows the correct information."
Context Variable
A temporary value that lives only on the current screen — when you navigate away, it disappears.
Analogy: A sticky note on your desk. It holds information temporarily while you work on this task. When you finish and move to a different task, you throw the sticky note away.
Example: "I used a context variable called 'SelectedBook' to pass the book the user clicked on to the Book Details screen."
Global Variable
A value that lives for the entire duration the app is open — all screens can read it.
Analogy: A whiteboard in the office that everyone can see. Anyone in any room can walk out, look at the whiteboard, and write on it.
Example: "I stored the logged-in user's name in a global variable called 'CurrentUser' when the app first opens. Every screen can display 'Hello, Rohit!' using this variable."
Delegation
When Power Apps lets the data source (Dataverse) do the filtering and sorting instead of downloading all the data to the app first.
Analogy: Two ways to find a book — (A) Take every book off the shelf and search through them yourself. (B) Ask the librarian: "Find me all Science books from 2020." Option B (delegation) is much faster.
Example: "My search formula uses Filter() which is a delegable function for Dataverse — Dataverse does the searching and only sends matching books to the app."
Concept — The Three Layers of a Canvas App

Every canvas app has three layers. Understanding these layers helps you design better apps and debug problems faster.

LAYER 1: PRESENTATION (what the user sees)
──────────────────────────────────────────────
Screens, Controls, Colors, Fonts, Layout
"What does it look like? Where do buttons go?"

        ↕ (connected by formulas)

LAYER 2: LOGIC (what the app does)
──────────────────────────────────────────────
Power Fx formulas, Variables, Navigation, Conditions
"What happens when a button is clicked? What data shows where?"

        ↕ (connected by connectors)

LAYER 3: DATA (what the app stores and reads)
──────────────────────────────────────────────
Dataverse tables, Variables, Collections
"Where does the information come from? Where does it go?"

Why this layering matters:

  • Wrong data → check Layer 3 (data source correct?) or Layer 2 (formula correct?)
  • Button does not respond → check Layer 2 (OnSelect formula correct?)
  • Layout wrong on phone → check Layer 1 (controls positioned for mobile screen size?)

Separating concerns — keeping presentation, logic, and data as independent as possible — is one of the most important principles in software architecture.

💭 System Thinking — What happens if we mix all three layers together?

Imagine the formula that calculates late fees is also responsible for displaying the button color. To change the button color, you must dig into the late fee formula. While editing, you accidentally change the fee calculation. Now fees are wrong.

This is called tight coupling — when two different concerns are tangled together. Changes in one area unexpectedly break other areas. Professional developers spend years untangling tightly coupled systems. We design loosely coupled systems from the beginning.

  • Name: Community Library → click Create

Step 2: Rename Screen1

  • In the left panel (Tree view), right-click Screen1 → Rename → name it: HomeScreen

Step 3: Add a header rectangle

  • Insert → Shapes → Rectangle. Set: X=0, Y=0, Width=Parent.Width, Height=80, Fill=RGBA(0, 120, 212, 1)

💭 Why RGBA values instead of a color picker?

If you pick a color with a color picker on 50 controls and a designer says "make all blue elements 10% darker," you must change 50 places. Define color once in a global variable (App.OnStart), change it once, and all 50 controls update automatically. This is the DRY principle — Don't Repeat Yourself.

Step 4: Add the search box

  • Insert → Text Input. Set: HintText="Search books by title or author...", X=20, Y=100, Width=Parent.Width - 40, Height=50, BorderRadius=8
  • Rename this control: SearchInput

Step 5: Add the books gallery

  • Insert → Blank Vertical Gallery
  • Set the Items property to: Search(Books, SearchInput.Text, "cr_title", "cr_author_name")
  • Inside the gallery template, add a Label for Title: ThisItem.cr_title
  • Add a Label for Author: ThisItem.cr_author_name
  • Add a Label for availability. Text: If(ThisItem.cr_available_copies > 0, "✓ Available", "✗ On Loan"). Color: If(ThisItem.cr_available_copies > 0, Green, Red)
  • Set the Gallery's OnSelect: Navigate(BookDetailScreen, ScreenTransition.Slide, {SelectedBook: ThisItem})
💭 System Thinking — What if the Dataverse table has 5,000 books?

With Dataverse as the data source, Search() is a delegable function — Dataverse does the searching and only returns matching books. But if you use Filter() with a non-delegable condition (using Left() or Len() inside Filter), Power Apps downloads only the first 500 rows, filters those locally, and misses books #501 onwards. Always check the yellow delegation warning triangle when writing a formula in the Items property.

Step 3: Add the Borrow button — the most important control in the app

  • Insert a Button. Text: "Borrow This Book"
  • Set Visible property: SelectedBook.cr_available_copies > 0 (button only shows when copies available)
  • Set OnSelect property to the formula below:
Patch(
  Loans,
  Defaults(Loans),
  {
    cr_book: {Id: SelectedBook.cr_bookid, '@odata.type': '#Microsoft.Dynamics.CRM.cr_book'},
    cr_member: {Id: LookUp(Members, cr_email = User().Email).cr_memberid, '@odata.type': '#Microsoft.Dynamics.CRM.cr_member'},
    cr_loan_date: Today(),
    cr_due_date: DateAdd(Today(), 14, TimeUnit.Days),
    cr_status: "Active"
  }
);
Notify("Book borrowed successfully! Due back by " & Text(DateAdd(Today(), 14, TimeUnit.Days), "dd mmm yyyy"), NotificationType.Success);
Navigate(HomeScreen)

What this formula does (line by line):

  • Patch(Loans, Defaults(Loans), {...}) — creates a NEW row in the Loans table
  • cr_book: ... — links this loan to the selected book using the book's ID
  • cr_member: LookUp(Members, cr_email = User().Email) — finds the logged-in user in the Members table
  • cr_loan_date: Today() — sets today as the borrow date
  • cr_due_date: DateAdd(Today(), 14, TimeUnit.Days) — sets due date to 14 days from today
  • Notify(...) — shows a green success message
  • Navigate(HomeScreen) — sends user back to home screen
💭 System Thinking — What if LookUp finds no match?

If Rohit's Microsoft account email is rohit@personal.com but the Member table has rohit@library.com, the LookUp returns blank. Patch then tries to create a loan with no member — which creates an orphaned record. This is a data quality issue. Professional systems validate at the form level. We add error handling in Week 6.

🗣️ English Practice — Week 5: "If X, then Y" — Conditional Sentences

Why this grammar pattern?

Canvas app logic IS conditional sentences written in a formula language. Understanding the English grammar of conditions helps you understand the app logic — and vice versa.

The pattern: "If [something is true], [result happens]."
In formulas: If(AvailableCopies > 0, "Borrow", "Waitlist")
In English: "If available copies is greater than zero, show 'Borrow'. Otherwise, show 'Waitlist'."

TypeStructureExample
Real presentIf + present, present"If the user is logged in, the app shows their loans."
Real futureIf + present, will + verb"If all copies are on loan, the system will show a waitlist message."
UnlikelyIf + past, would + verb"If every member borrowed 5 books at once, the library would run out of copies quickly."
Impossible/PastIf + past perfect, would have + verb"If we had not set up error handling, the app would have crashed."

For technical descriptions, use Real present and Real future most often.

🚫 Common English mistakes — Week 5

  • Mistake 1: "If I will click" ❌ "If I will click the button, the record will be saved." ✅ "If I click the button, the record will be saved." — After "If" in a real condition, always use PRESENT tense, never "will."
  • Mistake 2: "The data are" vs "The data is" — In modern professional English, "data is" is more common. Be consistent — pick one and stick to it.
  • Mistake 3: "Screenshotted" ❌ "I screenshotted the error." ✅ "I took a screenshot of the error."
  • Mistake 4: Starting every sentence with "I" ❌ "I built the home screen. I added a gallery. I connected it..." ✅ "I built the home screen and added a gallery connected to Dataverse. The gallery uses a filter formula that shows only matching books as the user types."

Power Fx — The Language Behind Everything

~3 hours · make.powerapps.com · Power Fx formula bar

Vocabulary — Week 6
Formula
A calculation or instruction written in Power Fx that tells a control what to do or show.
Analogy: A recipe instruction — "If the dough is not ready, wait 10 more minutes. Otherwise, put it in the oven." A formula makes decisions based on conditions.
Example: "The formula calculates available copies live: Text(SelectedBook.cr_total_copies - CountRows(Filter(Loans, cr_book.cr_bookid = SelectedBook.cr_bookid, IsBlank(cr_return_date))))."
Function
A built-in operation in Power Fx that does a specific job — like Filter, Sort, Patch, Navigate, Notify, LookUp, Today, DateAdd.
Analogy: Tools in a toolbox. A hammer (Patch), a measuring tape (DateDiff), scissors (Split). Each tool does one specific job.
Example: "The DateDiff() function calculates the number of days between two dates: DateDiff(cr_due_date, Today(), TimeUnit.Days)."
Collection
A temporary local table stored inside the app — not in Dataverse — just in the app's memory, lost when the app closes.
Analogy: A shopping basket. You pick items from the shelves (Dataverse) and put them in your basket (Collection) to review before finalising. The basket is temporary — it does not change the shop's inventory.
Example: "I created a Collection called 'SelectedGenres' to store which genre filters the user has turned on. When the user closes the app, the collection disappears."
Error Handling
Code or formulas that catch problems and respond gracefully instead of crashing.
Analogy: A safety net under a tightrope walker. If they fall, the net catches them. The performance does not stop — it continues.
Example: "My Borrow button formula has error handling: if the Patch fails, it shows 'Sorry, there was a problem borrowing this book. Please try again.' instead of a confusing technical error."
IfError
A Power Fx function that runs one formula and, if it fails, runs a different formula instead.
Example: IfError(Patch(Loans, ...), Notify('Borrow failed. Check your internet connection.', NotificationType.Error))
IsBlank
Checks if a value is empty — returns true if empty, false if it has a value.
Example: If(IsBlank(cr_return_date), 'On Loan', 'Returned') — if the return date is blank, the book has not been returned yet.
Concept — Power Fx Is Reactive (Functional Programming)

Power Fx formulas are different from traditional programming in one important way: they react to changes automatically.

Traditional code (step-by-step):

x = 5
y = x + 3   // y is now 8
x = 10      // y is STILL 8 — it calculated once and stopped

Power Fx (reactive — declares a relationship):

y = x + 3   // y is ALWAYS x + 3, no matter when x changes
// If x becomes 10, y automatically becomes 13

This is why when you type in the search box, the gallery updates instantly — you did not write "when the user finishes typing, refresh the gallery." Power Fx watches Search(Books, SearchInput.Text, ...) and automatically re-evaluates it every time SearchInput.Text changes.

💭 System Thinking — Advantages and limitations of reactive style

Advantages:

  • No need to write "event listeners" — Power Apps handles this
  • Fewer bugs — you declare relationships, not procedures
  • Easier for beginners to understand

Limitations:

  • Complex workflows (do step A, wait for result, then do step B based on result) are harder
  • Debugging is harder — when many formulas react to each other, tracking a bug requires thinking about the whole chain
  • Performance issues when formulas are complex and trigger on every keystroke
Exercise 4 — Improve the Borrow Formula with Error Handling

The current Borrow formula has 3 problems: (1) What if the loan record fails to save? (2) What if the user is not in the Members table? (3) What if Available Copies becomes negative because two people borrow at the same time? Let us fix each one.

Fix 1: Check if member exists before borrowing

  • Replace the OnSelect formula of the Borrow button with the full guarded version below:
If(
  IsBlank(LookUp(Members, cr_email = User().Email)),
  Notify("Your account is not registered as a library member. Please contact a librarian.", NotificationType.Error),
  Patch(
    Loans,
    Defaults(Loans),
    {
      cr_book: {Id: SelectedBook.cr_bookid, '@odata.type': '#Microsoft.Dynamics.CRM.cr_book'},
      cr_member: {Id: LookUp(Members, cr_email = User().Email).cr_memberid, '@odata.type': '#Microsoft.Dynamics.CRM.cr_member'},
      cr_loan_date: Today(),
      cr_due_date: DateAdd(Today(), 14, TimeUnit.Days),
      cr_status: "Active"
    }
  );
  Notify("Book borrowed successfully! Due back by " & Text(DateAdd(Today(), 14, TimeUnit.Days), "dd mmm yyyy"), NotificationType.Success);
  Navigate(HomeScreen)
)

Fix 2: Wrap Patch with IfError (network or server failure)

IfError(
  Patch(Loans, Defaults(Loans), {...}),
  Notify("Could not save the loan record. Please check your internet connection and try again.", NotificationType.Error)
)

Fix 3: Race condition — re-read Available_Copies from Dataverse just before borrowing

Set(LiveAvailableCopies, LookUp(Books, cr_bookid = SelectedBook.cr_bookid).cr_available_copies);
If(
  LiveAvailableCopies <= 0,
  Notify("Sorry, all copies were just borrowed. Please refresh and try again.", NotificationType.Warning),
  Patch(Loans, ...)
)
  • Test Fix 1: sign in as a user NOT in the Members table — does the error message appear instead of creating a loan?
  • Test Fix 3: manually set Available_Copies to 0 in Dataverse, then try borrowing — does the "all copies just borrowed" message appear?
The race condition — a senior architect concept

SelectedBook.cr_available_copies was read when you navigated to the Book Detail screen. If someone else borrowed the last copy 2 seconds later, this value is stale. LookUp(Books, ...) reads fresh data from Dataverse right now.

Three strategies for stale data: Optimistic locking (try to save, show conflict if someone else saved first — this is what we did), Pessimistic locking (lock the record when opened — safe but slow), Last-write-wins (simple but risky for financial data). You are learning senior architect concepts now.

🗣️ English Practice — Week 6: "Because... Therefore..." — Cause and Effect Chains

Why this grammar pattern?

Power Fx formulas are chains of logic: one thing causes another. Cause-effect language explains WHY you made a decision, WHY a formula works, or WHY something broke.

ConnectorUseExample
becausegives the reason"The formula uses DateDiff because we need to count days automatically."
thereforeshows the result"The delegation limit is 500 rows; therefore, we use a delegable function."
as a resultshows result (formal)"The filter is delegable. As a result, Dataverse does the work, not the app."
soshows result (casual)"The formula is reactive, so the gallery updates every time the user types."
due toreason before a noun"Due to the race condition risk, we re-read Available_Copies before borrowing."
which meansexplains a consequence"The formula is reactive, which means you never need to press a Refresh button."

Grammar practice

  1. Cause: Power Fx is reactive. Effect: Gallery updates automatically when search changes.
    "Power Fx is reactive, _______________________________."
  2. Cause: Non-delegable function used. Effect: Only first 500 rows searched.
    "We used a non-delegable function; _______________________________, only 500 rows are searched."
  3. Cause: Available_Copies stored statically. Effect: Two users can borrow last copy simultaneously.
    "We store Available_Copies as a static number. _______________________________ two users may simultaneously borrow the last copy."
  4. Cause: IfError added to Borrow formula. Effect: App shows friendly message instead of crashing.
    "We added IfError to the formula. _______________________________ the app shows a helpful message instead of a technical error."

Writing exercise: explain a formula in plain English

Pick any formula you wrote this week. Write a plain-English explanation using this structure:

  1. What the formula does (one sentence)
  2. Why we need it (cause — "because...")
  3. How it works step by step (then... then... then...)
  4. What happens if it fails (therefore... / as a result...)

Example: "The Borrow button formula creates a new loan record in the database. We need it because simply pressing a button does not save anything. The formula works in three steps: first, it checks whether the current user exists in the Members table; then, it re-reads the Available_Copies to prevent race conditions; finally, if both checks pass, it creates the loan record. If any step fails, the IfError function shows a friendly message — 'Could not save. Please try again.'"

🔊 Read aloud exercise

"The delegation problem occurs because Power Apps has a limit on how many rows it downloads from a data source at one time. This limit is 500 rows by default. If a formula is not delegable — meaning Dataverse cannot process the filter remotely — Power Apps downloads the first 500 rows, applies the filter locally, and returns results only from those 500 rows. As a result, if your library has 600 books and the book you searched for is number 601 in the database, it will not appear in the search results, even though it exists. This is a silent error — the app does not warn you. Therefore, always use delegable functions when working with large datasets."

Power Automate — When the App Sleeps, the Flows Run

~4 hours · make.powerautomate.com · Developer Plan environment

Vocabulary — Week 7
Trigger (Power Automate)
The event that starts a flow — like an alarm clock. When the alarm rings (trigger), you wake up (flow starts).
Types: Automated — triggered by a data event (new row created, row updated). Instant — triggered manually by a button click. Scheduled — triggered at a set time (every morning at 7 AM).
Example: "The overdue reminder flow uses a scheduled trigger: every morning at 7 AM, it wakes up and checks all loans. If any are overdue, it sends emails."
Condition
A decision point in a flow — "if this is true, do X; otherwise, do Y".
Analogy: A traffic light. Red (condition: is the light red?) → Stop (action if true). Green → Go (action if false).
Example: "In the overdue flow, there is a condition: 'Is Due_Date before Today?' If yes → send overdue email. If no → do nothing."
Loop
A part of a flow that repeats — "do this action for each item in a list".
Analogy: Sending invitations to a party. You have a list of 30 guests. A loop automates this: "for each guest in the list, send one invitation."
Example: "The overdue reminder flow uses an 'Apply to each' loop. It gets all overdue loans (a list of records), then for each overdue loan, it sends one email to that member."
Variable (Power Automate)
A temporary storage container in a flow — holds a value that you can read, change, and use later.
Analogy: A notepad you carry during a meeting. You write things down (set variable), cross out old values (update variable), and refer back to them (use variable).
Example: "I initialised a variable called 'TotalFee' at value 0. Inside the loop, for each overdue loan, I added the daily fee to TotalFee."
Parallel Branch
Two or more parts of a flow that run at the same time — not waiting for each other.
Analogy: A restaurant kitchen. Three cooks prepare salad, main course, and dessert simultaneously. The meal is ready much faster than if they worked one at a time.
Example: "When a new loan is created, one branch sends a confirmation email to the member (2 seconds), the other sends a notification to Pooja's Teams (1 second). Both happen simultaneously — total time: 2 seconds instead of 3."
Child Flow
A flow that is called (started) by another flow — it does one specific job and can be reused by many parent flows.
Analogy: A specialist consultant. The main project manager (parent flow) calls the legal consultant (child flow) whenever legal work is needed. The same consultant is used for multiple projects.
Example: "I created a child flow called 'Calculate Late Fee' that takes a loan date, a due date, and a fee-per-day rate, and returns the calculated fee. Three different parent flows call this child flow."
Concept — The Anatomy of a Well-Built Flow 
A WELL-BUILT FLOW:

1. TRIGGER
   └─ What starts this flow?
   └─ Be as specific as possible — "When a Loans row is created" not "When any record changes"

2. INITIALISE VARIABLES
   └─ Define all variables at the top — never inside loops
   └─ Give them clear names: TotalLateFees, not x or temp1

3. GET DATA
   └─ Query only what you need — use filters
   └─ Handle the empty case: what if no records are returned?

4. MAIN LOGIC (conditions and loops)
   └─ Each action focuses on one thing
   └─ Add comments to each step explaining WHY, not WHAT

5. ERROR HANDLING
   └─ "Configure run after" on key steps
   └─ If a step fails: log the error? Send an alert to Pooja?

6. COMPLETION
   └─ Send a summary if needed
   └─ Clean up temporary data
💭 System Thinking — Why is one giant flow dangerous?

Imagine the overdue loan flow does 9 things: check loans → calculate fees → send emails → update Dataverse → generate report → email report to Pooja → archive old loans → update member status → send Teams message.

If step 5 (generate report) fails, the flow stops. Steps 6-9 never run. Emails were already sent (step 3) but Dataverse was not updated (step 4 succeeded, step 5 failed). Your data is now inconsistent.

The rule: a flow should do ONE thing. If you need to explain it in a sentence and the sentence has more than one "and", it is probably doing too much. Use child flows for reusable parts.

🗣️ English Practice — Week 7: Active vs Passive Voice

Why this grammar pattern?

In technical writing, both active and passive voice are used — but for different purposes.

Active voice: The subject DOES the action.

  • "The flow sends the overdue reminder email."
  • "Power Automate creates the loan record."
  • "Pooja approves the membership request."

Passive voice: The action is DONE TO the subject.

  • "The overdue reminder email is sent by the flow."
  • "The loan record is created automatically."
  • "The membership request was approved."

Use passive when: who does the action is unimportant or unknown ("The database was updated at 7 AM"), in documentation describing processes ("New members are approved within 48 hours").

Use active when: in most everyday technical writing (clearer and more direct), when responsibility matters ("Pooja must approve new members"), in user instructions ("Click the Borrow button").

Grammar practice — transform between active and passive

Active → Passive:

  1. "The scheduled flow checks all overdue loans every morning at 7 AM."
    Passive: "All overdue loans _________________________ every morning at 7 AM."
  2. "Power Automate sends an approval email to Pooja when a new member registers."
    Passive: "An approval email _________________________ to Pooja when a new member registers."

Passive → Active:

  1. "The due date is calculated automatically by the system."
    Active: "The system _________________________."
  2. "The late fee was determined by the library committee in 2025."
    Active: "The library committee _________________________."

Model-Driven App + Dataverse Security + Power BI (Personal)

~5 hours · make.powerapps.com + app.powerbi.com · Developer Plan environment

Vocabulary — Week 8
Security Role
A named collection of permissions in Dataverse — it defines what records a user can Create, Read, Update, and Delete, and at what scope (just their own records, their team's records, or all records in the organization).
Example: "The 'Library Member' security role allows: Read all Book records (so members can search the catalog), Create Loan records only for themselves, and Read their own Member record. They cannot see other members' records at all."
CRUD
Create, Read, Update, Delete — the four basic operations you can do on any data. Every permission system in the world is built on these four actions.
Example: "Neha (Junior Librarian) has CRUD permissions on Book records but only Read on Loan records. She can add new books but cannot change or delete loan history."
Business Rule
Logic enforced at the Dataverse level — a rule that applies no matter which app, tool, or API touches the data.
Analogy: A bank rule that says you cannot withdraw more than your balance. This rule applies whether you use the ATM, the website, or the mobile app — the rule lives at the bank level.
Example: "I created a Dataverse business rule: if Total_Copies is changed to less than (Total_Copies - Available_Copies), show an error — 'You cannot reduce total copies below the number currently on loan.'"
View (model-driven app)
A saved filter and column configuration for a table — "show me all overdue loans, sorted by member name, showing these 5 columns".
Example: "I created an 'Overdue Loans' view: filter where Status = Active AND Due_Date < Today, sorted by Due_Date ascending. Every librarian uses this view to see the worst overdue loans first."
DAX (Data Analysis Expressions)
A formula language used in Power BI to create calculated measures and columns. Like Excel formulas, but for Power BI — works across the entire dataset, not just a cell.
Example: Overdue Rate = DIVIDE(COUNTROWS(FILTER(Loans, Loans[Status] = "Active" && Loans[DueDate] < TODAY())), COUNTROWS(FILTER(Loans, Loans[Status] = "Active")))
