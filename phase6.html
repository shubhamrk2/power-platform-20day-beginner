Phase 6 · Days 17–20

Power BI

Turn data into charts and dashboards that help people decide. This four-day track is browser-first (Power BI Service) and sets you up for the PL-300 certification. Great news: you already learned two of the four Power BI steps in earlier phases.

Day 17

Power BI: what it is, Service vs Desktop, and datasets

~100 minutes

Concept — what is Business Intelligence (BI)?

Power BI turns raw data into charts, tables and dashboards that help people see what's going on. If a spreadsheet answers "what are the numbers?", Power BI answers "what do they mean, at a glance?" Every Power BI project has four steps — and you already know the first two:

Concept — Service (browser) vs Desktop (app)
  • Power BI Service — the website app.powerbi.com. Runs in your browser, so you can use it now: bring in data, build reports, make dashboards, share.
  • Power BI Desktop — a free Windows app (needs installing). Where pros do the richest modelling and write DAX. Almost everything here works in the Service; when you get a laptop, Desktop will feel familiar (and PL-300 assumes it).
Concept — dataset, report, dashboard

Three similar-sounding, different things:

  • A dataset (or semantic model) is the prepared, linked data a report reads from.
  • A report is one or more pages of charts built on a dataset.
  • A dashboard is a single screen pinning the most important visuals — an at-a-glance summary.
Do this — get in, and bring your own data
  • Incognito → app.powerbi.com; start the free Power BI trial if asked. Find Workspaces and My workspace.
  • Try a built-in Sample report; click a bar and watch other charts react ("everything filters everything").
  • Make a small Excel file: sheet Sales with Date, Product, Region, Amount and ~15 made-up rows.
  • My workspace → New / Get data → Files → Local file → upload → Import. A dataset appears.
Tip — Import vs DirectQuery Import copies data into Power BI (fast, most common). DirectQuery leaves it in the source and queries live (for very large or always-fresh data). For learning, pick Import.
Words you learned today
  • Power BI / BI — turning data into charts & dashboards / using data to understand at a glance.
  • Service / Desktop — browser version / free Windows app for rich modelling & DAX.
  • Dataset / report / dashboard — prepared data / pages of charts / a one-screen summary.
  • Import vs DirectQuery — copy data in vs query live in place.
Check yourself Name the four steps of a Power BI project (Get & clean → Model → Visualise → Share) and confirm your Sales dataset is in My workspace.
Day 18

Your first report: visuals

~110 minutes

Concept — visuals, fields, cross-filtering

A visual is a chart, table, or number-box. You build one by dragging fields (columns) into it; Power BI groups and totals automatically. The magic: click part of one visual and every other visual filters to match — called cross-filtering.

The visuals you'll use most: Card (one big number), bar/column (compare categories), line (a trend over time), table/matrix (detail; matrix = a pivot table), and slicer (an on-screen filter people click).

Do this — build a one-page report
  • Open the Sales dataset → Create report. The canvas opens in the browser.
  • Add a Card; drag Amount in → Total sales.
  • Add a Clustered column chart: Region on the axis, Amount as value.
  • Add a Line chart: Date on the axis, Amount as value.
  • Add a Slicer on Product; click a product and watch every visual react. Save the report as Sales Overview.
Tip — ask in plain English Add a Q&A visual and type "total amount by region" — Power BI builds the chart for you. Great for exploring and for showing people.
Words you learned today
  • Visual / field — a chart/table/card / a column you drag into it.
  • Cross-filtering — clicking one visual filters the others.
  • Slicer / matrix — an on-screen filter / a pivot-table-style visual.
Check yourself A report with a card, bar chart, line chart, and slicer — and cross-filtering works. That's a real, interactive report.
Day 19

Modelling, Power Query & DAX

~120 minutes · this day covers modelling and calculations

Concept — the star schema

Real reports use several linked tables (the relationships from Day 3). BI's favourite shape is the star schema: a central fact table (the events/numbers — each Sale) with surrounding dimension tables (the things you slice by — Product, Region, Date). It makes reports faster and formulas simpler.

Concept — Power Query returns, and DAX arrives

Power Query (from Day 13) cleans data here too — promote headers, change types, filter. Then comes DAX (Data Analysis Expressions), Power BI's formula language — "Excel formulas for whole tables and totals." You make:

  • A measure — a calculation that recomputes for whatever you're looking at (e.g. Total Sales changes when you click a Region). The important one.
  • A calculated column — a new column worked out row-by-row.
Do this — model, then write measures
  • Add a second table Products (Product, Category) matching your Sales product names. In Model view, drag Product from Sales to Products to create a relationship.
  • Build a chart of Amount by Category — only possible because the tables are linked.
  • New measure: Total Sales = SUM(Sales[Amount]) → put it in a Card.
  • Order Count = COUNTROWS(Sales) and Avg Sale = AVERAGE(Sales[Amount]); click a slicer and watch them recompute.
  • Optional: a calculated column Big Order = IF(Sales[Amount] > 100, "Yes", "No"); use it as a slicer.
Careful — modelling & DAX are richest in Desktop The browser Service does basic modelling, but relationships, the star schema, and DAX are far smoother in Power BI Desktop (free, Windows). When you have a laptop, redo this day in Desktop — it's what PL-300 assumes.
Words you learned today
  • Model / star schema — tables + relationships / fact in the middle, dimensions around.
  • Fact / dimension table — the numbers/events / the things you slice by.
  • DAX — Power BI's formula language.
  • Measure / calculated column — a total that respects filters / a per-row value.
  • SUM / AVERAGE / COUNTROWS / IF — starter DAX functions.
Check yourself You linked two tables and wrote measures that react to a slicer. You understand the key idea: a measure is a total that respects context.
Day 20

Dashboards, sharing, RLS — capstone & what's next

~120 minutes · the finish line

Concept — dashboards, sharing, and row-level security

You pin the best visuals onto a dashboard (a one-screen summary), publish into a workspace, and share (often as a Power BI app; sharing needs a Pro licence or Premium capacity). Row-Level Security (RLS) shows different rows to different people — e.g. each regional manager sees only their region — by defining a role with a rule and assigning people to it. It's the same least-privilege instinct as Dataverse security (Day 4) and DLP (Day 16).

Do this — publish, pin, and glance at RLS
  • Make sure Sales Overview is saved in a workspace.
  • On a visual, click pin → New dashboard = Sales Dashboard; pin two or three visuals.
  • Open the dashboard; click a tile and see it jump to the report.
  • Explore Share / Manage permissions to understand access (don't share anything real). Find where Row-level security is set (on the dataset's Security) and read it.
Do this — your capstone (ties the whole course together)
  • Data: in My Learning Solution, add a table Request (Requester, Book, Status choice New/Approved/Rejected, Requested-on date) with 2 rows.
  • App: a small canvas app to submit a request (form + Submit) and list requests (gallery).
  • Automation: a flow — when a Request is added, start an approval; on approve set Status = Approved and email the requester; on reject set Rejected.
  • AI (optional): point Library Helper at a short FAQ about requests and publish.
  • BI: upload/refresh a small requests dataset in app.powerbi.com and build a report of requests by Status. Pin it to a dashboard.
Concept — your certification path

PL-900 (Power Platform Fundamentals) covers Days 1–16; PL-300 (Power BI Data Analyst) covers this phase. Both have free study paths on learn.microsoft.com. For PL-300's hands-on parts, install Power BI Desktop (free) when you have a laptop. When the trial ends, keep practising free on the Power Apps Developer Plan (powerapps.microsoft.com/developerplan) — a personal environment, no card, no expiry.

Words you learned today
  • Dashboard / pin / workspace / app — a summary screen / add a visual to it / where content lives / a shareable bundle.
  • Power BI Pro — the licence usually needed to share.
  • Row-level security (RLS) — showing different rows to different viewers.
  • PL-900 / PL-300 — the Fundamentals / Power BI Data Analyst certifications.

That's a real, job-relevant foundation. Now go earn PL-900 and PL-300. Be proud. 🌱
