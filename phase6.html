Phase 6 · Days 17–20

Power BI — in depth

Turn data into charts and dashboards that help people decide. This is the biggest phase, mapped to Microsoft's official Power BI learning paths and the PL-300 certification. It's browser-first, with a proper Desktop setup guide below. You already learned two of Power BI's four steps in earlier phases — now we go deep on all four.

Setup

Power BI setup guide — read this first

Do this before Day 17 · ~30 minutes

Concept — the two Power BI tools, and which to use

Power BI comes in two parts that work together:

  • Power BI Service — the website app.powerbi.com. Runs in your browser (so you can use it now). Where you share reports, make dashboards, and manage workspaces. You can also build simple reports here.
  • Power BI Desktop — a free Windows app you install. Where professionals get data, clean it with Power Query, model it, and write DAX. It has the full toolset. The PL-300 exam assumes Desktop.

Plan for a beginner with no personal laptop: do everything you can in the Service (browser), and treat Desktop as the "when you have a Windows laptop" tool. Where a step is Desktop-only, this course says so and gives the browser alternative.

Do this — get set up
  • In an incognito window, go to app.powerbi.com and sign in with the learning account. If prompted, start the free Power BI trial (usually no card).
  • Look for Workspaces (left) and My workspace — your personal area. This is where your datasets, reports and dashboards will live.
  • If you have a Windows laptop (optional but recommended for PL-300): install Power BI Desktop free from the Microsoft Store (search "Power BI Desktop") or powerbi.microsoft.com/desktop. Open it and sign in with the same account.
  • Bookmark Microsoft's free training (links in the box below). You'll follow this course, and dip into those modules for extra depth.

Day 17

Get started & get data

~110 minutes · Learn path: Get started with Power BI

Concept — what Power BI is for

Power BI connects to your data, lets you clean and model it without changing the source, helps you visualise what matters, and lets you share it. If a spreadsheet answers "what are the numbers?", Power BI answers "what do they mean, at a glance?" Every project follows four steps — and you already know the first two:

Concept — where data comes from (connectors)

Power BI can connect to hundreds of data sources through the Get data button: files (Excel, CSV), databases (SQL Server), online services, the web, and — importantly for you — Dataverse and SharePoint (the data you built earlier!). You pick a source, sign in if needed, and choose the tables you want.

Concept — dataset, report, dashboard
  • A dataset (or semantic model) is the prepared, linked data a report reads from.
  • A report is one or more pages of charts built on a dataset.
  • A dashboard (Service only) is a single screen pinning the most important visuals.
Your Power BI report uses YOUR project — not a new file This whole phase builds a report on the Loan data from your Community Library. Nothing new to invent: Loan is the fact (each borrowing), and Book, Member and Date are what you slice by.
Do this — get your project's data into Power BI
  • Best (Desktop): open Power BI Desktop → Get data → Dataverse → sign in to your Learning environment → load Loan, Book, Member. This connects Power BI straight to your project.
  • Browser-only alternative: use the Loan and Member Excel files you exported on Day 16 (plus a quick Books export). In app.powerbi.com → My workspace → New / Get data → Files → Local file → upload → Import. A dataset appears.
  • Choose Import (know when you'd use DirectQuery — see the tip below).
  • Open the built-in Sample report in the Service; click a bar and watch other charts react ("everything filters everything") to see where you're heading.
Tip — Import vs DirectQuery When you connect, you often choose a storage mode: Import copies a snapshot into Power BI (fast, most common, refreshed on a schedule); DirectQuery leaves data in the source and queries it live (for very large or always-fresh data, with some limits). For learning, choose Import.
Words you learned today
  • Data source / Get data — where data comes from / the button to connect.
  • Dataset / report / dashboard — prepared data / pages of charts / a one-screen summary.
  • Storage mode: Import vs DirectQuery — copy a snapshot in vs query live in place.
Check yourself Name the four steps, and confirm your Loan (and Book, Member) data is loaded into Power BI. Bonus: which storage mode would you pick for a 2-billion-row always-live database? (DirectQuery.)
Day 18

Build visuals & reports

~120 minutes · Learn path: Build Power BI visuals and reports

Concept — the report canvas and its three panes

A report is built on a canvas with three panes on the right: Data (your tables and fields), Visualizations (chart types and where to drop fields), and Filters. You add a visual, then drag fields onto it; Power BI groups and totals automatically.

Concept — the visuals you'll use most
  • Card — one big number (e.g. Total Loans). KPI — a number vs a target.
  • Bar / column chart — compare categories.
  • Line chart — a trend over time.
  • Table / matrix — detail rows; a matrix groups rows and columns (a pivot table).
  • Slicer — an on-screen filter people click (e.g. pick a Membership).
  • Map, pie/donut, treemap, gauge — use thoughtfully; bars and lines are usually clearest.
Concept — three levels of filter, and interactions

Filters apply at three scopes: visual (this chart only), page (every visual on the page), and report (every page). Separately, cross-filtering means clicking part of one visual filters the others — you can even change how visuals interact (Format → Edit interactions). Drill-down lets you click into a hierarchy (Year → Quarter → Month), and drill-through jumps to a detail page for the thing you clicked.

Do this — build two report pages with 9 specific visuals
  • Open your dataset → Create report. Rename the first page to Loan Overview. You'll build 5 visuals here.
  • Visual 1 — Card (Total Loans): click the Card visual. Field well: Values = Loan (count of rows, or your Total Loans measure). Title: "Total Loans". Format: font size 20, white background, teal accent bar.
  • Visual 2 — Card (Open Loans): second Card. Values = Open Loans measure. Title: "Open Loans". Red accent bar so it stands out. Place the two cards side-by-side at the top.
  • Visual 3 — Clustered Column Chart (Loans by Genre): X-axis = Book[Genre]. Y-axis = Loan (count). Title: "Loans by Book Genre". Turn on Data labels. Sort by count descending: click the "..." → Sort by → count.
  • Visual 4 — Line Chart (Loans over time): X-axis = Loan[Loan date]. Y-axis = count of Loans. Title: "Loans Over Time". This shows borrowing trends. If you have a Date table, use Dates[Month] on X for a cleaner month-by-month line.
  • Visual 5 — Slicer (by Membership): Slicer visual. Field = Member[Membership]. Style: Dropdown (Format → Slicer settings → Dropdown). Click "Student" — all 4 charts filter to student loans only. Click "Clear" to reset. This is cross-filtering in action.
  • Add a page-level filter: Filters pane → Add filter (Page level). Field = Loan[Status]. Select "Open" and "Overdue" only. Now the whole page shows only active loans. Title the page filter "Active loans view".
  • Add Page 2: click + at the bottom → rename Member Analysis. Build 4 visuals here.
  • Visual 6 — Pie Chart (Members by Membership type): Legend = Member[Membership]. Values = Member (count). Turn off the pie in future — for learning this is fine. Title: "Members by Type". Note: pie charts work OK with 4-5 slices; bars are clearer at 6+.
  • Visual 7 — Table (Overdue Loans detail): Table visual. Columns: Book[Title], Member[Full name], Loan[Loan date], Loan[Due date], Loan[Late fee]. Add a filter on this visual: Loan[Status] = Overdue. This gives staff a list of overdue loans to chase.
  • Visual 8 — KPI (Returned vs target): KPI visual. Value = Returned Loans measure. Target = Total Loans measure. Trend axis = Loan date. A green arrow if returns exceed the target fraction.
  • Visual 9 — Q&A visual: add the Q&A visual. Click it → type count of loans by genre as bar chart. Power BI builds the chart from natural language. Save the report as Library Loans.
Tip — good charts, not fancy charts Reach for a bar/column to compare and a line for time. Pies are hard to read past a few slices. Clarity beats decoration — that's a genuine PL-300 theme.
Words you learned today
  • Visual / field / field well — a chart / a column you drag / the slots you drop fields into.
  • Filter (visual / page / report) — a filter at three scopes.
  • Cross-filtering / drill-down / drill-through — click-to-filter / dig into a hierarchy / jump to detail.
  • Formatting / Q&A — styling a visual / ask for a chart in plain English.
Check yourself A report with a card, bar, line and slicer, styled, with a page filter, and you used Q&A. That's an interactive, presentable report.
Day 19

Prepare & model: Power Query, relationships & DAX

~140 minutes (the deepest day) · Learn paths: Data analytics + Model data

Concept — prepare data with Power Query (it returns!)

On Day 13 you cleaned a CSV with Power Query. Power BI uses the same tool in Transform data. Each thing you click becomes an Applied step you can re-order or delete — a recipe you can re-run any time the source changes.

Concept — the transforms that matter, and query folding

Common steps: promote headers, change type, filter rows, remove/rename columns, split/merge columns, group by, merge queries (join two sources), append queries (stack two tables). Advanced: query folding — where possible, Power Query pushes work back to the source as a native query (fast); certain steps break folding, after which work happens locally.

Concept — modelling: relationships, cardinality, star schema

Real reports use several linked tables (the relationships from Day 3). A relationship has a cardinality — usually one-to-many (one Book, many Loans) — and a filter direction. BI's favourite shape is the star schema: a central fact table (the numbers/events) surrounded by dimension tables (the things you slice by). Add a dedicated Date table so time features work.

Concept — DAX: measures, columns, and context

DAX (Data Analysis Expressions) is Power BI's formula language — "Excel formulas for whole tables and totals." A measure recomputes for whatever you're looking at (the filter context); a calculated column is worked out row-by-row and stored. The powerful function is CALCULATE, which changes the filter context; and time-intelligence functions (like TOTALYTD) need that Date table.

Total Loans  = COUNTROWS(Loan)
Open Loans   = CALCULATE(COUNTROWS(Loan), Loan[Returned] = false)
Fiction Loans = CALCULATE([Total Loans], Book[Genre] = "Fiction")
Loans YTD    = TOTALYTD([Total Loans], 'Dates'[Date])
Do this — clean, model, build all DAX measures, and add the Date table
  • Power Query — clean your tables: Transform data → open Member query → promote headers if needed → set column types: Full name (text), Email (text), Join date (date), Active (true/false). Check Loan query: Loan date and Due date → set to Date type. Applied steps should show 3-5 steps. Close & Apply.
  • Model view — relationships: switch to Model view (left sidebar icon). Connect: Loan[Book] → Book[BookID] (drag from the Loan column to the Book column). Cardinality: Many-to-one. Cross-filter direction: Single (Book filters Loan). Same for Loan[Member] → Member[MemberID]. You now have a star schema: Loan is the fact, Book and Member are dimensions.
  • Build all 8 DAX measures: for each, click Modeling → New measure and type the formula exactly:
    Total Loans = COUNTROWS(Loan)
    Open Loans = CALCULATE(COUNTROWS(Loan), Loan[Returned] = FALSE())
    Returned Loans = CALCULATE(COUNTROWS(Loan), Loan[Returned] = TRUE())
    Overdue Loans = CALCULATE(COUNTROWS(Loan), Loan[Status] = "Overdue")
    Avg Loan Days = AVERAGEX(Loan, DATEDIFF(Loan[Loan date], Loan[Due date], DAY))
    Late Return Rate = DIVIDE(CALCULATE(COUNTROWS(Loan), Loan[Status] = "Overdue"), COUNTROWS(Loan), 0)
    Avg Days Overdue = AVERAGEX(FILTER(Loan, Loan[Status] = "Overdue"), DATEDIFF(Loan[Due date], TODAY(), DAY))
    And after adding the Date table below: Loans YTD = TOTALYTD([Total Loans], 'Dates'[Date])
  • Date table (Desktop): Modeling → New table → type exactly: Dates = CALENDARAUTO(). Power BI scans all date columns and builds a continuous date range. Add calculated columns to Dates:
    Year = YEAR('Dates'[Date])
    Month = FORMAT('Dates'[Date], "MMMM")
    Month number = MONTH('Dates'[Date])
    Quarter = "Q" & QUARTER('Dates'[Date])
    Day of week = FORMAT('Dates'[Date], "dddd")
    Is weekend = WEEKDAY('Dates'[Date], 2) >= 6
    Then mark it as a date table: right-click Dates → Mark as date table → Date column = Date. Now relate: Dates[Date] → Loan[Loan date] (many-to-one, Dates side = one).
  • Put Total Loans, Open Loans, Overdue Loans in Cards. Add Loans YTD in a Card. Slicer on Member[Membership] → watch all measures recompute as you click different membership types. This is the filter context at work.
Careful — this day is much richer in Desktop Power Query, the model view, relationships, the star schema, and DAX are all far smoother in Power BI Desktop (free, Windows). The browser Service can do basics. When a laptop is available, redo Day 19 in Desktop — it's exactly what PL-300 tests.
Words you learned today
  • Applied steps / query folding — the recorded transform recipe / pushing work to the source.
  • Merge / append — join two sources / stack two similar tables.
  • Relationship / cardinality / star schema — a table link / how many-to-how-many / fact + dimensions shape.
  • DAX / measure / calculated column — the formula language / a filter-aware total / a per-row value.
  • CALCULATE / time intelligence — change the filter context / date-based measures (YTD, last year).
Check yourself You shaped data in Power Query, linked two tables, and wrote measures that react to slicers. Key idea: a measure is a total that respects context — and CALCULATE is how you bend that context.
Day 20

Share, secure & maintain — plus your capstone

~130 minutes · the finish line · Learn path: Build visuals & reports

Concept — publish, workspaces, apps, and dashboards

From Desktop you Publish a report to a workspace in the Service. You pin the best visuals onto a dashboard (a one-screen summary), and you package a workspace's content as a Power BI app for consumers. Sharing needs a licence: Pro per-user, or Premium / Fabric capacity for large audiences.

Concept — refresh, and row-level security (RLS)

Imported data goes stale, so you set a scheduled refresh (an on-premises gateway is needed for some sources). Row-Level Security (RLS) shows different rows to different people — e.g. each regional manager sees only their region — by defining a role with a DAX rule and assigning people to it. Same least-privilege idea as Dataverse security (Day 4) and DLP (Day 16). You may also see sensitivity labels and endorsement (Promoted / Certified datasets) for governance.

Do this — publish, create RLS, pin a dashboard, schedule refresh, and export the .pbix
  • Publish (Desktop): File → Publish → Publish to Power BI. Sign in if asked. Choose My workspace. Open the link → your report appears in the Service.
  • Create an RLS role (Desktop): Modeling → Manage roles → + New role. Name = LibraryStaff. Select the Member table. In the Table filter DAX expression box, type: [Email] = USERPRINCIPALNAME(). This means: when a LibraryStaff user views the report, the Member table is filtered so they only see their own row. Save. Now go back to the Service.
  • Assign users to RLS role (Service): open your dataset → Security (three dots → Security). Find LibraryStaff → + Add people. Add your own email address. Save. Now click Test as role → LibraryStaff — the report filters to only your Member row. Click "Now viewing as: LibraryStaff" → Stop viewing. This is exactly how an admin would verify RLS before deployment.
  • Build the dashboard: on the Loan Overview page, hover over the Total Loans card → pin icon → New dashboard. Name = Library Dashboard. Pin it. Go to pin Loans by Genre chart → Existing dashboard → Library Dashboard. Pin Loans Over Time → same dashboard. Open the dashboard: click any tile → it jumps back to the report page with full interactivity.
  • Share (read only): on the dashboard → Share → enter an email address. They need a Power BI Pro licence to view. With the M365 E5 trial, your learning account has Pro. Read-only viewers cannot see the underlying data, only the visuals.
  • Scheduled refresh: dataset → Settings → Scheduled refresh. Toggle On. Frequency = Daily. Time = 6am. Add your email for refresh failure notifications. For the Dataverse connector this works without a gateway (cloud-to-cloud). For a file-based source (local Excel), you'd need to install the on-premises data gateway on your PC.
  • Save the .pbix permanently: Desktop → File → Save as → choose a folder → save as library-loans.pbix. Or in Service → File → Download this file (.pbix). This file contains your model, all visuals, and all DAX — your entire Power BI project in one portable file.
Do this — your capstone (ties the whole course together)
  • Data: in My Learning Solution, add a Request table (Requester, Book, Status choice, Requested-on) with 2 rows.
  • App: a small canvas app to submit a request and list requests.
  • Automation: a flow — when a Request is added, start an approval; on approve set Status = Approved and email the requester.
  • AI (optional): point Library Helper at a short requests FAQ and publish.
  • BI: build a Power BI report of requests by Status (connect to Dataverse in Desktop, or upload a requests Excel in the Service), add a Total Requests measure, and pin it to a dashboard.
Concept — your certification path

PL-900 (Power Platform Fundamentals) covers Days 1–16; PL-300 (Power BI Data Analyst) covers this whole phase. Free study on learn.microsoft.com: the Power BI training hub lists every path, and there's a practice assessment for PL-300. For the hands-on exam skills, use Power BI Desktop (free) when you have a laptop. When the trial ends, keep practising free on the Power Apps Developer Plan (powerapps.microsoft.com/developerplan).

Words you learned today
  • Publish / workspace / app — send a report to the Service / where content lives / a shareable bundle.
  • Dashboard / pin — a one-screen summary / adding a visual to it.
  • Scheduled refresh / gateway — keeping imported data current / the bridge to some sources.
  • Row-level security (RLS) — different rows for different viewers.
  • PL-900 / PL-300 — the Fundamentals / Power BI Data Analyst certifications.
