Phase 1 · Days 1–4

Foundations

Before you build anything, get comfortable with the cloud, and learn how data is stored and shaped. These four days are the ground everything else stands on.

Day 1

Getting your bearings: the cloud, Microsoft 365, Power Platform

~75 minutes

Concept — what is "the cloud"?

Plain English: "the cloud" means powerful computers in a data centre somewhere that you use through your web browser. You don't install anything — you open a website, sign in, and the work happens on Microsoft's computers, not yours. That's why any computer with a browser works.

A bit more technical: the tools are web applications. Your browser sends requests over the internet to Microsoft's servers, which do the work and send back the screen you see. Your creations are saved on those servers, so you can sign in from any device and find them again.

Concept — the words: browser, tab, URL, sign-in
  • Browser — the program for visiting websites (Microsoft Edge, Google Chrome). It came with your computer.
  • Tab — one website open inside the browser, like a page in a book.
  • URL / address — a website's address you type at the top, e.g. make.powerapps.com.
  • Sign in — proving who you are with email + password, so the site shows your stuff.
Concept — what is the Power Platform?

Plain English: a family of Microsoft tools for building useful things — apps, automations, chatbots, reports — mostly by clicking and dragging, with little or no traditional coding (called "low-code").

  • Power Apps — build apps. Phase 2.
  • Power Automate — build automations. Phase 3.
  • Copilot Studio — build AI chatbots. Phase 5.
  • Power BI — build charts and dashboards. Phase 6.
  • Dataverse — the shared database underneath it all. Day 2.
Do this — open incognito, sign in, find your room
  • Open a private / incognito window: Edge or Chrome, press Ctrl+Shift+N (Mac: Cmd+Shift+N).
  • Type make.powerapps.com and press Enter. Sign in with the learning account from Day 0.
  • Top-right: click the environment picker and choose Learning. Do this every time you start.
  • Explore the left menu (Home, Apps, Tables, Flows…) — this is the maker portal, your workshop. Don't create anything yet.
Tip — why incognito matters A private window forgets sign-ins when closed and ignores accounts used elsewhere. That prevents the common headache of the site silently logging you in as the wrong account.
Words you learned today
  • Cloud — computers you use over the internet through a browser.
  • Browser / tab / URL — the program for websites / one open site / a site's address.
  • Incognito window — a browser window that forgets everything when closed.
  • Power Platform — Microsoft's low-code family (Apps, Automate, Copilot Studio, BI, Dataverse).
  • Tenant / environment — your whole cloud space / one room inside it ("Learning").
  • Maker portal — make.powerapps.com, where you build.
Check yourself Can you (1) open an incognito window, (2) sign in at make.powerapps.com, and (3) switch to the Learning environment? If yes, you're ready for Day 2.
Day 2

Dataverse: tables, columns, and rows

~90 minutes

Concept — a database is a spreadsheet on steroids

If you've seen an Excel spreadsheet, you already understand most of this:

  • A table is like one sheet — it holds one kind of thing (e.g. all your Books).
  • A column (a field) is one piece of information about it (Title, Author, Pages).
  • A row (a record) is one actual thing (the book "Matilda").

Dataverse is the Power Platform's database — stricter and more powerful than a spreadsheet: each column has a fixed type, tables can link, and access is controlled.

Concept — data "types"

Every column stores one kind of value so the computer knows how to treat it: Text (short words), Whole number (counts), Decimal/Currency (money), Date, Choice (pick from a fixed list), Yes/No (a switch). If Pages is a number, the computer can total it; as text it couldn't.

Do this — build a "Book" table
  • Left menu → Tables → New table. Display name = Book. Create.
  • Rename the existing primary column (the main label) to Title.
  • + New column for each, picking the right type: Author (Text — for now), Pages (Whole number), Published (Date only), Genre (Choice: Fiction, Non-fiction, Textbook), In stock (Yes/No).
  • Open the table's data grid and add 3 made-up rows.
Tip — friendly names vs logical names Behind your friendly Display name (what people read), Dataverse keeps a logical name with a prefix like cr123_title (what the system uses). You don't need to worry about it yet.
Words you learned today
  • Database / Dataverse — an organised store of info / the Power Platform's database.
  • Table / column / row — a kind of thing / a field about it / one actual thing.
  • Data type — the kind of value a column holds.
  • Primary column — the main label column for each row.
Check yourself You have a Book table with 5+ columns and 3 rows. Which type for a phone number — number or text? (Text — phone numbers can start with 0 and you never do maths on them.)
Day 3

Linking data: choices, lookups, and relationships

~90 minutes

Concept — why not put everything in one table?

Imagine every book also stored the author's country and birth year. If an author wrote 10 books, you'd type their details 10 times — and fix 10 rows if they changed. Instead we keep Authors in their own table once, and point each book to its author. That pointing is a relationship — the core idea of good data design: store each fact once, then link.

Concept — choice vs lookup
  • A choice is a pick-list of fixed words you decide in advance (Genre: Fiction / Non-fiction / Textbook). The options are part of the column's design.
  • A lookup points to a row in another table (Author points to a row in the Author table). The options are live data that grows as you add rows.

Rule of thumb: short, unchanging list → choice; a pointer to a "thing" with its own details → lookup.

Do this — grow the project's data model: Author, Member, Loan
  • Tables → New table = Author. Rename its primary column to Full name; add Country (Text), Born (Date). Add 2–3 authors.
  • Open Book → delete the old text Author column → + New column → type Lookup → Related table = Author. Set each book's author by picking from your Author rows.
  • New table Member (rename primary column to Full name): add Email (Text), Join date (Date), Membership (Choice: Standard / Student / Senior). Add 3 members.
  • New table Loan — the heart of your project. Columns: Book (Lookup → Book), Member (Lookup → Member), Loan date (Date), Due date (Date), Returned (Yes/No), Status (Choice: Open / Returned / Overdue).
  • Add 3–4 Loan rows, each linking a real Book to a real Member with dates. (You just recorded borrowing events.)
Tip — why the Loan table matters Loan points to two other tables (Book and Member) — two relationships in one table. It records an event (a borrowing), which is exactly what a Power BI report measures later: in Phase 6, Loan becomes the "fact" table, and Book, Member and Date become the things you slice by. Everything connects.
Words you learned today
  • Relationship — a link between two tables.
  • Choice (option set) — a fixed pick-list defined in the column.
  • Lookup — a column that points to a row in another table.
  • One-to-many (1:N) — one row relates to many rows on the other side.
Check yourself Book rows now link to real Author rows. Is "Marital status: Single / Married / Other" better as a choice or a lookup? (Choice — a short fixed list with no extra details behind each option.)
Day 4

Keeping it tidy: environments, solutions, security

~75 minutes

Concept — a "solution" is a moving box

As you build tables, apps and flows, they can scatter. A solution is a labelled box you put related things into, so you can find them and later move the whole box between environments (e.g. from a testing room to a live one). Professionals build inside solutions from day one. A solution has a publisher with a short prefix — a name tag added to everything you create.

Concept — security roles

A security role is a set of permissions — can this person read, create, edit, delete rows? In your Learning environment you're the admin, so you can do everything. In a real company, most people get limited roles so they only touch what they should.

Do this — create a solution and adopt your tables
  • Solutions → New solution = My Learning Solution. New publisher: name Learner, prefix learn.
  • Open it → Add existing → Table → add all four project tables: Book, Author, Member, Loan.
  • Add one environment variable to see how settings are stored: in the solution → New → More → Environment variable → name LoanPeriodDays, type Number, current value 14. (You'll use it in a flow later.)
  • From now on, build everything inside this solution so the whole project stays in one movable box (this is also how you'll back it up — see "Keep it forever" on the home page).
  • Peek: admin.powerplatform.microsoft.com → Environments → Learning. Just look at its settings, users and capacity.
Tip — "managed" vs "unmanaged" (you'll meet this on Day 16) While you build, your solution is unmanaged (editable). When you ship it to a live environment it's usually exported as managed (locked). More on that in Phase 5.
Words you learned today
  • Solution — a box grouping related components so you can manage and move them.
  • Publisher / prefix — the name tag added to what you create (e.g. learn_).
  • Security role — a set of permissions (who can do what).
  • Managed / unmanaged — locked (shipped) vs editable (in-progress) solution.
  • Environment variable — a stored setting (like LoanPeriodDays) you can change without editing apps or flows.
Check yourself You have My Learning Solution containing your two tables. Foundations complete — now you get to build apps. 🎉
