Phase 4 · Days 12–14

Data & integration

Real solutions pull data from many places. You'll set up a Community Library SharePoint team site (list + library + automation), bulk-import members with a dataflow and Power Query, then explore how Power Platform talks to the outside world through connectors, HTTP, Office Scripts, and custom connectors.

Day 12

SharePoint: team sites, lists, libraries, views, and notifications

~100 minutes

Concept — SharePoint site types

SharePoint is Microsoft 365's team collaboration layer. Two site types:

  • Team site — internal, team-first. Has a Members list (M365 group), a default document library, and a News section. Best for a team actively building together.
  • Communication site — broadcast-first. No M365 group. Designed for a wider audience to consume content (announcements, policies, portals). No editing by viewers.

For the Community Library, use a Team site — the whole team needs to add events and upload policies.

Concept — lists vs Dataverse tables

SharePoint lists are lighter and simpler than Dataverse tables. Use a list when:

  • The data is document-centric or already lives in M365.
  • You need simple tracking without business rules or complex relationships.
  • The audience are regular M365 users with no Power Apps licence.

Use Dataverse when you need relationships between tables, business rules, security roles, or the data feeds a canvas / model-driven app seriously.

Concept — list column types in SharePoint
  • Title — the default primary text column (rename it to match your purpose).
  • Single line / Multiple lines of text — short vs long text.
  • Date and Time — date only or date+time.
  • Number / Currency — numeric values.
  • Choice — a fixed pick-list (similar to Dataverse Choice).
  • Yes/No — a checkbox.
  • Person or Group — a pointer to a user in the tenant.
  • Lookup — a pointer to an item in another list on the same site.
Do this — build the Community Library SharePoint site
  • microsoft365.com → app launcher (grid icon) → SharePoint → Create site → Team site. Site name = Community Library. Description = Event calendar and library policies. Privacy = Private. Click Next → Finish.
  • On the site: + New → List. Name = Library Events. Click Create.
  • Add these columns to Library Events:
    • Title column already exists — rename it to Event name (click column header → Column settings → Rename).
    • + Add column → Date and Time — Name: Event date, type: Date only.
    • + Add column → Single line of text — Name: Location.
    • + Add column → Multiple lines of text — Name: Description.
    • + Add column → Number — Name: Capacity.
    • + Add column → Yes/No — Name: Confirmed, default = Yes.
  • Add 3 rows of made-up events: e.g. "Book club meeting", "Summer reading launch", "Author talk".
  • Create a custom view: click the view dropdown (top right) → Create new view. Name = Confirmed events. Filter: Confirmed is equal to Yes. Sort: Event date ascending. Save. This is exactly how you'd filter a view in Dataverse (Day 3) — same concept.
  • Turn on versioning: Settings (gear icon, top right) → List settings → Versioning settings. Set "Create a version each time you edit an item" = Yes. Save. Now every edit is tracked — you can restore an old version.
  • + New → Document library — Name: Policies. Create. Upload a text file called borrowing-rules.txt (write two fake sentences). The library stores the file PLUS any columns you add (that's "metadata").
  • Power Automate notification flow: go to make.powerautomate.com → Solutions → My Learning Solution → New → Automation → Cloud flow → Automated. Trigger = When an item is created (SharePoint). Site address = your Community Library site. List name = Library Events. Add step: Post message in a chat or channel (Teams). Post in = Channel. Team and Channel = (any channel you have, or use General). Message = Expression: concat('New event: ', triggerOutputs()?['body/Title'], ' on ', triggerOutputs()?['body/Event_x0020_date']). Save and test by adding a new event row.
Tip — SharePoint's "5,000 item limit" Past about 5,000 items in a list, some views and filters that don't use an indexed column become very slow. You'll never hit this in learning. But knowing the number (and that you fix it by indexing a column or using filtered views) is useful in interviews.
Words you learned today
  • Team site / Communication site — internal team collaboration / broadcast to a wide audience.
  • List / library / item — a simple table / file storage with columns / one row or file.
  • Metadata — the columns of information attached to a document in a library.
  • Versioning — tracking every change so you can restore previous versions.
  • Custom view — a saved filter+sort+column-selection for a list.
Check yourself You built a SharePoint team site with a list (6 columns, custom view, versioning) and a document library, and a flow that posts to Teams when a new event is added. Could you explain in one sentence when you'd use a list instead of a Dataverse table?
Day 13

Importing and cleaning data: dataflows, Power Query, and the M language

~120 minutes

Concept — what is a dataflow?

A dataflow is a pull → clean → load pipeline that runs on a schedule:

  • Pull — connect to a source: CSV, Excel, SharePoint list, SQL Server, web URL, or many others.
  • Clean — transform the raw data visually in Power Query.
  • Load — write the clean rows into a Dataverse table (or SharePoint list).

The same Power Query editor appears in Power BI (Day 19) — learning it here gives you two skills at once.

Concept — Power Query transforms and the M language

Every click in Power Query generates a line of M code in the Applied steps list. You never need to write M by hand, but reading it helps you understand what's happening. Common transforms:

  • Use first row as headers — promotes row 1 to column names.
  • Change type — sets each column to the correct data type (Text, Number, Date…).
  • Remove columns — drops columns you don't need.
  • Rename columns — gives columns cleaner names.
  • Custom column — adds a new column with a formula (M syntax, similar to Excel).
  • Filter rows — keeps only rows matching a condition.
  • Group by — aggregates rows (like a pivot table — count orders per customer).
  • Merge queries — joins two sources like a VLOOKUP/SQL JOIN.
  • Append queries — stacks two tables with the same columns.

The Advanced Editor shows the full M code for your query. It looks like this for a simple CSV import:

let
  Source = Csv.Document(File.Contents("new-members.csv"),
             [Delimiter=",", Columns=4, Encoding=65001, QuoteStyle=QuoteStyle.None]),
  #"Promoted Headers" = Table.PromoteHeaders(Source, [PromoteAllScalars=true]),
  #"Changed Type" = Table.TransformColumnTypes(#"Promoted Headers",
                     {{"First name", type text}, {"Last name", type text},
                      {"Email", type text}, {"Membership", type text}}),
  #"Custom Column" = Table.AddColumn(#"Changed Type", "Full name",
                      each [#"First name"] & " " & [#"Last name"], type text)
in
  #"Custom Column"

Each step is: StepName = Transform(PreviousStep, ...). The last step is what flows into the load.

Concept — upsert (key column): update instead of duplicate

When you load into Dataverse, you can choose a load type:

  • Load to new entity / create — inserts every row as new every time. Run it twice → duplicates.
  • Load to existing entity (upsert) — picks a key column (e.g. Email). For each row: if a Dataverse row already has that Email, update it; if not, insert it. Run it ten times → no duplicates.

Always use upsert for imports that will be re-run.

Do this — bulk-import members with a dataflow
  • Create new-members.csv in Notepad with this exact content (8 rows + header):
First name,Last name,Email,Membership
Priya,Sharma,priya.sharma@example.com,Student
Rahul,Gupta,rahul.gupta@example.com,Standard
Aisha,Khan,aisha.khan@example.com,Premium

Sophie,Laurent,sophie.laurent@example.com,Student

  • make.powerapps.com → Dataflows → New dataflow. Name = Import members. Click Create. In the connector list, choose Text/CSV. Click Browse → upload new-members.csv. Click Next.
  • In Power Query editor: click Use first row as headers (if not already). Select all four columns → right-click → Change type → Text.
  • Click Add column → Custom column. Name = Full name. Formula = [#"First name"] & " " & [#"Last name"]. OK.
  • Click Advanced editor — read the M steps. Confirm the Added Custom Column step. Close.
  • Click Next. Under "Load settings", choose Load to existing table → select the Member table. Map columns: Full name → Full name, Email → Email, Membership → Membership. Set Key column = Email. Click Publish.
  • The dataflow runs automatically. Check your Member table — 8 new rows. Change one row in the CSV and re-publish the dataflow → confirm it updates the changed row rather than inserting a duplicate.
  • Optional — schedule it: open the dataflow → Settings → Scheduled refresh. Set to run daily at 7am. This would keep Dataverse in sync with an external system that updates the CSV.
Tip — dataflow vs cloud flow A dataflow is for bulk loading/cleaning on a schedule. A cloud flow (Power Automate) is for event-driven per-record automation. A classic beginner mistake is using a cloud flow in a loop to import 5,000 rows — use a dataflow instead.
Words you learned today
  • Dataflow — a pull-clean-load pipeline into Dataverse, runnable on a schedule.
  • Power Query — the visual transformation editor (shared between dataflows and Power BI).
  • M — the formula language Power Query writes behind every click.
  • Applied steps — the recorded list of transforms; each is one M statement.
  • Upsert / key column — update existing rows matching the key column, insert the rest.
Check yourself You imported 8 members from a CSV, added a Full name computed column, and confirmed re-running doesn't duplicate. Open the Advanced Editor — you should be able to read each step even if you can't write M from memory yet.
Day 14

Connectors, APIs, Office Scripts, and custom connectors

~120 minutes

Concept — connectors: the bridges Power Platform uses

Power Automate, Power Apps, and Power BI all talk to external services through connectors. A connector wraps an API into a list of ready-made triggers and actions so you don't need to write code. There are three tiers:

  • Standard connectors — included in base Power Automate/Apps licences. SharePoint, Outlook, Teams, OneDrive, Forms, Excel Online, Planner.
  • Premium connectors — require a premium licence (Developer Plan counts). Dataverse, HTTP, SQL Server, Salesforce, custom connectors.
  • Custom connectors — you build a wrapper around any REST API that doesn't have a Microsoft-made connector.
Concept — what is an API?

An API (Application Programming Interface) is the "ordering window" of a program — a defined set of ways other programs can ask it to do things or return data. On the web, most APIs use REST:

  • You send a request to a URL (called an endpoint) using an HTTP verb: GET (fetch data), POST (create/send data), PATCH (update), DELETE (remove).
  • You often include an API key or OAuth token in a header to prove who you are.
  • The response comes back as JSON — structured text that looks like nested key-value pairs.

When Power Automate uses a connector, it's making these REST calls for you behind the scenes.

Concept — the HTTP action: calling any API without a connector

The HTTP premium action lets you call any REST API directly from a flow:

  • Method — GET / POST / PATCH / DELETE.
  • URI — the full URL of the endpoint.
  • Headers — key-value pairs: e.g. Content-Type: application/json, Authorization: Bearer <token>.
  • Body — JSON payload for POST/PATCH.

The response body is a JSON string. Use Parse JSON action (next step) to turn it into tokens you can use in dynamic content.

Concept — Office Scripts: TypeScript inside Excel

Office Scripts (Excel Online only, not desktop) let you automate Excel with TypeScript. You can:

  • Record actions and read the generated script.
  • Return a value from the script — Power Automate can read that return value as an action output.
  • Accept parameters — your flow passes values in, the script uses them.

This bridges Power Automate ↔ Excel when the Excel Online connector's built-in actions aren't enough (e.g. complex cell formatting, reading a named range, applying a formula).

Concept — custom connectors: wrapping your own API

A custom connector wraps a REST API that doesn't have a Microsoft connector, so every flow-maker in your environment can use it without knowing the raw API details. You provide:

  • Host URL — the base address of the API.
  • Authentication type — API key, OAuth 2.0, Basic auth, or No auth.
  • Operations (actions/triggers) — each one maps to one API endpoint with a verb.

You can also import an OpenAPI / Swagger spec and the connector builds itself from that file.

Do this — Office Script + HTTP action + peek at custom connectors
  • Office Script: go to microsoft365.com → Excel → create a new blank workbook. Add headers in A1:D1: Book | Member | Loan date | Due date. Add 3 rows of made-up loan data.
  • In Excel Online: Automate → Record Actions. Bold row 1 (click row 1 header → Ctrl+B). Stop recording. Open the script. You'll see TypeScript like:
function main(workbook: ExcelScript.Workbook) {
  let sheet = workbook.getActiveWorksheet();
  let range = sheet.getRange("1:1");
  range.getFormat().getFont().setBold(true);
}
  • Modify the script to return a value: change the last line to return sheet.getUsedRange().getRowCount();. Change the function signature to function main(workbook: ExcelScript.Workbook): number. Save the script as Count rows.
  • In Power Automate: create an Instant flow. Add Run script (Excel Online). Location = OneDrive for Business. File = your workbook. Script = Count rows. Add Send me an email notification. Body = Dynamic content → Result (the return value from Run script). Test it — you should receive an email with the row count.
  • HTTP action (read-only): in a flow, add HTTP action. Method = GET. URI = https://openlibrary.org/api/books?bibkeys=ISBN:0451524935&jscmd=data&format=json. Run the flow. In Run history, click the HTTP action output → see the JSON response for George Orwell's 1984. This is a real public API with no API key required.
  • After the HTTP action, add Parse JSON. Content = Body (from HTTP). Click Generate from sample and paste the JSON output. Now the fields appear as dynamic content for later steps.
  • Custom connector tour: Power Automate → Custom connectors → + New connector → Create from blank. Name = Open Library API. Look at: (1) General tab — host, base URL; (2) Security — choose "No auth" for this public API; (3) Definition tab — + New action, name it "Get book by ISBN", set verb GET, path /api/books, add query parameter bibkeys (string, required). Don't save — just click Cancel after exploring. You've seen every piece a connector has.
Tip — you don't need to master all of this today The goal is vocabulary: API (a program's ordering window), REST/HTTP (how web programs talk), GET/POST (fetch vs send), JSON (the reply format), custom connector (your bridge to any API). Being able to say "I've used the HTTP action and I know how custom connectors are structured" is genuinely useful in interviews.
Words you learned today
  • Connector / custom connector — a ready-made bridge / one you build to wrap any web API.
  • API / REST / HTTP verb / JSON — a program's ordering window / web communication standard / GET/POST/PATCH/DELETE / the reply format.
  • Endpoint / header / body — the URL of an API operation / metadata for the request / the request payload.
  • Office Script — a TypeScript automation in Excel Online, callable from Power Automate flows.
  • Parse JSON — a Power Automate action that turns a JSON string into usable dynamic content tokens.
