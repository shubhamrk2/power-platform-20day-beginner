Phase 4 · Days 12–14

Data & integration

Real solutions pull data from many places. You'll use SharePoint, import and clean data with dataflows and Power Query, and learn how systems talk to each other through connectors and APIs.

Day 12

SharePoint: lists and document libraries

~90 minutes

Concept — what is SharePoint?

SharePoint is the part of Microsoft 365 for team sites, shared file storage, and simple lists. A list is a simple table (columns and rows), lighter than Dataverse. A document library stores files (Word, PDF, images), where each file can also have columns of information ("metadata").

Do this — make a list and automate it
  • microsoft365.com (app launcher ▦) → SharePoint → Create site → Team site = Learning Site.
  • On the site: + New → List = Tasks; columns Owner (Text), Due (Date), Done (Yes/No). Add a few items.
  • + New → Document library = Files; upload a harmless sample file.
  • Power Automate: automated flow, trigger When an item is created (SharePoint) → your site → Tasks → email yourself the new task's Title.
Tip — the "5,000 item" number SharePoint lists work great for hundreds/low thousands of items. Past ~5,000, some views need special handling. You'll never hit it here, but mentioning it shows you know the boundary.
Words you learned today
  • SharePoint — M365's team sites, lists, and file storage.
  • List / library / item — a simple table / file storage with columns / one row.
  • Metadata — the columns of info attached to a file.
Check yourself A SharePoint site with a list and library, and a flow that reacts to new items. Could you say when you'd pick a list over a Dataverse table?
Day 13

Importing and cleaning data: dataflows & Power Query

~110 minutes

Concept — getting outside data in

Often the data you want already lives in a spreadsheet. A dataflow pulls it in, cleans it, and loads it into a Dataverse table — on a schedule if you want. Like a conveyor belt from a messy source to a tidy table. The visual cleaning tool inside is Power Query; behind your clicks it writes a language called M.

Do this — import a spreadsheet into Dataverse
  • Make a tiny CSV (Notepad → people.csv): header row FirstName,LastName,Department,Status + ~6 made-up rows.
  • make.powerapps.com → Dataflows → New dataflow → Text/CSV → upload.
  • In Power Query: Use first row as headers; set column types; filter Status = Active; add a custom column FullName = FirstName & " " & LastName.
  • Load to a new table, set a key column (so re-runs update, not duplicate), Publish, then check the table.
  • Open Advanced editor to read the M your clicks produced (just read it).
Tip — dataflow vs flow (they sound alike) A dataflow is for bulk loading/cleaning on a schedule. A cloud flow (Power Automate) is for event-driven, per-record automation. Using a cloud flow to bulk-import thousands of rows is a classic beginner mistake — use a dataflow.
Words you learned today
  • Dataflow — a scheduled pull-clean-load into Dataverse.
  • Power Query / M — the visual cleaning editor / the language behind it.
  • Key column (upsert) — the match column so re-imports update instead of duplicating.
Check yourself You turned a raw CSV into a clean Dataverse table. Re-run it and confirm it updates rather than duplicating — that's the key column working.
Day 14

Talking to other systems: connectors, APIs, Office Scripts

~110 minutes

Concept — connectors and the idea of an API

A connector is a ready-made bridge to a service. To connect to something without a ready-made bridge, you build a custom connector. It helps to know what an API is: a way for one program to ask another for information or to do something — like a waiter taking your order to the kitchen. On the web, programs talk using REST: you send a request to a URL with a verb like GET (fetch data) or POST (send data), and get back a reply, usually in JSON (structured text).

Concept — Office Scripts

Office Scripts let you record or write little automations inside Excel on the web — format a sheet, read a table — then run them from a Power Automate flow. They're written in TypeScript, but you can start by recording your actions and reading what it wrote.

Do this — an Office Script, then peek at connectors
  • Open Excel on the web (via microsoft365.com → Excel → blank). Type a few values.
  • Automate → Record Actions; format a cell, type a value, Stop. Open the script and read the TypeScript it generated.
  • Edit the script to return a value (see the README sample). Save.
  • In Power Automate: add Run script (Excel Online) → pick your workbook & script → run and watch the sheet change.
  • Optional peek: Power Automate → Custom connectors → New → Create from blank; just look at the General / Security / Definition tabs to see how you'd wrap a web API.
Tip — you don't need to master APIs today Carry away the vocabulary: API (a program's ordering window), REST/HTTP (how web programs talk), GET/POST (fetch vs send), JSON (the reply format), custom connector (your own bridge). That's plenty.
Words you learned today
  • Connector / custom connector — a ready-made bridge / a bridge you build to any web API.
  • API / REST / GET / POST / JSON — a program's ordering window / web rules / fetch / send / reply format.
  • Office Script — a TypeScript automation in Excel-on-web, callable from a flow.
Check yourself You ran an Office Script from a flow and can explain in one sentence what an API is. Big step in seeing how systems connect.
