Master glossary

Every term from the course — plain meaning plus a library-project example so you can see it in context.

TermPlain meaningLibrary example
CloudComputers you use over the internet through a browser — no software to install, Microsoft manages the hardware.The whole library system (books, loans, members) lives in Microsoft's cloud; Ashwini can access it from any device.
Incognito / private windowA browser window that forgets sign-ins and cookies when closed — keeps your personal account separate from the learning account.Open an incognito window to sign in as member@learning.onmicrosoft.com while staying signed into personal Gmail in the normal window.
TenantYour organisation's dedicated, isolated space in Microsoft's cloud — one Microsoft 365 subscription = one tenant.The trial tenant learning.onmicrosoft.com is the "library's building" — all environments, apps, and users for this course live inside it.
EnvironmentA container inside the tenant for a specific set of apps, flows, and data. Environments are isolated — the wrong environment picker is the #1 cause of "missing" components.PP-DEV is where you build the library app. PP-TEST is where you import the managed solution for testing. Never build directly in production.
Maker portalmake.powerapps.com — the browser-based studio where you build canvas apps, flows, tables, and solutions. Always check the environment dropdown (top-right) before you start.You open the maker portal, switch to PP-DEV, and create the cl_book table — all in the browser, no software to install.
PPACPower Platform Admin Center (admin.powerplatform.microsoft.com) — for admins to manage environments, DLP policies, licenses, and capacity. Makers don't normally go here.An admin uses PPAC to apply a DLP policy that blocks the HTTP connector in PP-DEV so learners can't accidentally call external APIs.
DataverseThe Power Platform's built-in managed relational database — like Excel but with relationships, security roles, audit logs, and an API. Required for model-driven apps.The library stores its Books, Members, and Loans tables in Dataverse. A loan row knows which book and which member it belongs to via lookup columns.
TableA grid of rows and columns in Dataverse — like a spreadsheet tab, but with types, rules, and relationships. Has a display name (Book) and a schema name (cl_book) with a publisher prefix.The library has three custom tables: cl_book, cl_member, cl_loan — all under the "cl" (Community Library) publisher prefix.
Column (Field)One piece of information stored per row — like a spreadsheet column but typed. Every table has a primary column (the row's "name"). Custom columns get a publisher prefix: cl_title, cl_email.cl_book has columns: cl_title (Text), cl_author (Text), cl_genre (Choice), cl_isbn (Text). cl_loan has cl_loan_date (Date), cl_returned (Yes/No).
Row (Record)One item in a table — a specific book, a specific member, or a specific loan. Every Dataverse row has a unique GUID as its primary key.Rohit Verma's "Premium" membership is one row in cl_member. His 10 loan records are 10 rows in cl_loan, each pointing back to him via a lookup.
GUIDGlobally Unique Identifier — a 36-character hex string that uniquely identifies every Dataverse row. Format: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx. You can't delete a row and reuse its GUID.When the overdue-reminder flow fetches Rohit's loan, it uses his member GUID in the OData filter: _cl_member_value eq guid'3f4a...' — not his name.
Data typeThe kind of value a column holds — Text, Whole Number, Decimal, Currency, Date Only, Date & Time, Choice, Lookup, Yes/No, Image, File. Choosing the right type prevents bad data.cl_loan_date is Date Only (not Date & Time) so the overdue calculation uses whole days. cl_late_fee is Currency so it displays with a ₹ symbol automatically.
Choice columnA column with a fixed pick-list of values — stored as integers, displayed as labels. Prevents free-text spelling errors. Two kinds: Local (this column only) or Global (shared across tables).cl_membership_type Choice column: Premium, Standard, Student, Senior — stored as integers 1–4. The canvas app shows the labels; OData filters use the integers.
Lookup columnA column that stores a pointer (GUID) to a row in another table — creating a relationship. Shows as a searchable dropdown in forms. In OData, referenced as _fieldname_value.cl_member lookup on the cl_loan table links each loan to one member. In the canvas app, LoanForm.Item.'cr_member (Members)' navigates the relationship.
Relationship (1:N)A link where one row in Table A relates to many rows in Table B. Created by adding a Lookup column on the "many" side. Ensures referential integrity — you can't create a loan for a non-existent member.Member 1:N Loans (one member, many loans). Book 1:N Loans. The loan table holds both lookup columns — two foreign keys — creating the many-to-many bridge between Books and Members.
OData filterThe query language for filtering Dataverse rows via REST API. Appended to the URL: ?$filter=expression. Used in flow "List rows" actions and PAC CLI. Operators: eq, ne, lt, gt, and, or. Functions: contains(), startswith().The overdue-reminder flow uses: cl_returned eq false and cl_due_date lt @{utcNow()} — fetches only loans that are not returned and whose due date is in the past.
SolutionA zip-like deployment container holding all components (apps, flows, tables, roles, environment variables, connection references). Everything promoted to UAT or PRD must be inside a solution.The "Community Library v1.0" solution contains: 2 canvas apps, 3 Dataverse tables, 4 flows, 1 model-driven app, 2 environment variables, 3 security roles.
Publisher / prefixThe creator's stamp on a solution. All custom tables and columns get the publisher prefix: cl_book, cl_member. Default Dataverse publisher prefix is cr. The prefix prevents naming collisions when multiple solutions share an environment.The library solution uses publisher "Community Library" with prefix cl. A second solution for HR would use prefix hr — their columns never collide even in the same environment.
Managed solutionA solution exported in locked/read-only mode. Imported to UAT or PRD — nobody can edit apps or flows directly in that environment. All fixes must go through DEV → export → re-import. Enforces discipline.The library app is deployed to PP-TEST as a managed solution. Ashwini can run it and test it, but cannot accidentally change the approval logic at 5 pm on Friday.
Unmanaged solutionThe editable version in DEV. All components are fully customizable. When you export, you choose managed (for UAT/PRD) or unmanaged (for backup or sharing with another developer). DEV always holds unmanaged.In PP-DEV, the unmanaged solution lets you add a new column to cl_book, update the canvas app, and export a new managed version to PP-TEST.
Environment variableA named value stored in a solution that holds different values per environment — without changing any code. Types: String, Number, Boolean, JSON, Data Source. Set during solution import.LoanPeriodDays = 14 in PP-DEV (generous for testing) and 7 in PP-PRD. The overdue flow reads this variable — no code change when promoting.
Connection referenceA solution-level named pointer to a connection. The actual connection (auth credentials) is set per-environment during the import wizard — no code changes needed between DEV and PRD."LibraryOutlookRef" connection reference → dev@learning.onmicrosoft.com in PP-DEV, noreply@library.org in PRD. Same flow, different sender per environment.
ALMApplication Lifecycle Management — the discipline of moving apps through DEV → UAT → PRD in a controlled, repeatable, auditable way. In Power Platform: build in DEV (unmanaged), test in UAT (managed), run in PRD (managed).Day 4 of the course. You export the library solution as managed and import it to PP-TEST. This is exactly how enterprise Power Platform teams deploy apps — no cowboy changes in production.
Security roleA permission set defining what a user can Create, Read, Write, Delete on each Dataverse table. Users get both an environment role (Basic User or System Admin) and one or more security roles."Library Member" role: Read own loans only (User scope), Read all books (Organization scope), no access to admin tables. "Librarian" role: full CRUD on all library tables.
Access level (privilege scope)The scope of a permission in a security role: User (own rows only), Business Unit (own team), Organization (all rows). This is what drives row-level security without any code.Fatima Ansari has "Read" at User scope on Loans — she sees only her 5 loan rows. The librarian has "Read" at Organization scope — they see all 99 loans.
Canvas appAn app where you design every pixel — drag controls onto screens, set properties with Power Fx formulas. Best for custom UX, mobile apps, or matching a specific design.The "Library Member App" lets Ashwini browse books, check her loans, and see her due dates — custom colors, logo, and navigation, all designed in the maker portal.
Model-driven appUI auto-generated from your Dataverse schema — you configure views and forms, not pixels. Best for data-heavy admin portals with standard layouts. Always requires Dataverse.The "Librarian Portal" model-driven app lets staff manage books, view all loans, and process returns — standard list + detail form layouts, zero UI design effort.
Control / propertyAn element on a canvas app screen (Button, Label, TextInput, Gallery, Form) and a setting on it (Text, OnSelect, Fill, Visible). Properties are set with Power Fx formulas.The "Borrow Book" Button control: Text = "Borrow", OnSelect = Patch(cl_loan, Defaults(cl_loan), {cl_member: varCurrentMember, cl_book: Gallery.Selected}).
Power FxThe Excel-like formula language of canvas apps. Declarative, comma-separated, dot-notation. Different from Power Automate's expression language — same platform, completely different syntax.Filter(cl_loan, 'cr_member (Members)'.cr_email = User().Email && cr_returned = false) — shows only the current member's active loans in the gallery.
Filter() / Search()Filter(table, condition) returns matching rows using Power Fx (works with Dataverse natively — delegable). Search(table, text, "column") does a contains-text search on a specific column.Gallery Items: Filter(cl_book, IsBlank(SearchInput.Text) || cr_title starts with SearchInput.Text) — shows all books when the search box is empty, filters by title as you type.
Patch()Creates or updates a Dataverse row in a canvas app. Patch(table, Defaults(table), {col: val}) creates a new row. Patch(table, existing_record, {col: val}) updates a specific row.Patch(cl_loan, Defaults(cl_loan), {cl_book: Gallery.Selected, cl_member: varCurrentMember, cl_loan_date: Today(), cl_due_date: DateAdd(Today(), 14, Days)}) — borrows a book.
User().EmailPower Fx function returning the signed-in user's email address (UPN). Use it to filter data so each user sees only their own rows — the foundation of row-level security in canvas apps.The member app's gallery Items: Filter(cl_loan, 'cr_member (Members)'.cr_email = User().Email) — Fatima sees her 5 loans; Rohit sees his 10 loans. Same app, different data.
Variable (canvas app)A labelled memory box for one value — set with Set(varName, value), read by name. UpdateContext({localVar: value}) for screen-scoped variables. Used to remember the selected member, current screen state, etc.Set(varCurrentMember, LookUp(cl_member, cr_email = User().Email)) on app start — stores the signed-in member's full record for use in Patch and filter formulas throughout the app.
GalleryA canvas app control that repeats a template for every row in a data source — like a list view. The Items property is a Power Fx expression. Gallery.Selected holds the tapped item.The book gallery: Items = Filter(cl_book, cr_available = true). Each card shows title, author, and genre. Tapping a card sets Gallery.Selected for the detail screen.
Form (EditForm / DisplayForm)Controls for viewing or editing one Dataverse row. SubmitForm() saves, NewForm() clears, ResetForm() discards. Form.Valid is true only when all required fields are filled.The loan form: EditForm connected to cl_loan, pre-populated with Gallery.Selected. "Return Book" button checks LoanForm.Valid, then calls SubmitForm(LoanForm) and Patch(cl_loan, LoanForm.LastSubmit, {cl_returned: true}).
DelegationLetting the Dataverse server execute heavy operations (Filter, Sort, Search) rather than downloading all rows to the device. Without delegation, Power Apps fetches only the first 500 rows — dangerous for large datasets.The library has 5,000 books. Filter(cl_book, cr_genre = Dropdown.Selected.Value) is delegable (Dataverse handles it). Filter(cl_book, Len(cr_title) > 10) is not — the blue delegation warning appears.
ViewA saved filtered + sorted + column-selected list of Dataverse rows. Displayed in model-driven apps and Dataverse. Reusable — one view can be used across multiple apps. Created in the table designer."Overdue Loans" view: Filter = cl_returned eq false and cl_due_date lt Today(), sorted by cl_due_date ascending. The librarian portal uses this view on its Loans page.
Business ruleNo-code if-then logic applied at the Dataverse table level. Runs server-side. Can: show/hide fields, set field values, validate, lock fields, display error messages. Cannot access related tables.Business rule on cl_loan: if cl_returned = true, make cl_return_date required and lock cl_due_date. Fires automatically when staff edit a loan row in any app.
Flow (Cloud Flow)A server-side automated workflow in Power Automate. One trigger + one or more actions. Runs in Microsoft's cloud — no computer needs to be on. Three trigger types: Automated, Scheduled, Instant."Daily Overdue Reminder" — Scheduled trigger at 9 AM, List overdue loan rows from Dataverse, Apply to each loop, send email to each member. Runs every day without Ashwini touching anything.
TriggerWhat starts a flow. Every flow has exactly one. Automated (event-based), Scheduled (time-based), Instant (button click), PowerApps (called by a canvas app or Power Apps button).The "New Loan Created" flow uses an Automated trigger: "When a row is added" on cl_loan. It fires the moment a member borrows a book — sends a confirmation email within seconds.
ActionOne step inside a flow that does something — Get a row, Send an email, Post to Teams, Condition (if-else), Apply to each (loop), Scope (error handling), Initialize variable, Compose.Action 1: "List rows" — gets all overdue loans from cl_loan. Action 2: "Apply to each" — loops over results. Action 3: "Send an email" — emails each member their overdue book details.
ConditionAn if-else branch in a flow. Evaluates a true/false expression. Yes branch and No branch can each contain more actions. Can be nested for complex logic.Condition: "Is cr_days_overdue greater than 30?" Yes → send escalation email + create admin task. No → send standard reminder email. One condition, two different outcomes.
Apply to eachA loop that runs actions for every item in an array — usually the output of a "List rows" action. Equivalent to forEach in code. Watch out for performance limits on large datasets."Apply to each" over the 8 overdue loan rows from "List rows." Inside: a Condition checking days overdue, then the appropriate email action — 8 iterations, 8 emails sent.
Expression (flow)Formula language inside Power Automate — different from Power Fx. Based on Azure Logic Apps expression language. Key functions: utcNow(), addDays(), formatDateTime(), outputs(), items(), ticks().Due date expression: addDays(triggerBody()?['cr_loan_date'], 14) — 14 days after the loan date. Formatted for email: formatDateTime(items('Apply_to_each')?['cr_due_date'], 'dd MMM yyyy').
ScopeA container action that groups other actions — primarily used for try/catch error handling. Set the "catch" scope's "Configure run after" to "has failed" — it runs only when the try scope fails.Scope "Try": update loan row. Scope "Catch" (runs if Try fails): send alert email to librarian@library.org with result('Try')?[0]['error']['message'] — catch any Dataverse write errors.
Child flowA flow designed to be called by a parent flow. Trigger: "Manually trigger a flow" with input parameters. Must end with "Respond to a PowerApp or flow" to return outputs. Must be in the same solution."Calculate Late Fee (Child)" — receives DaysOverdue (number), returns LateFee (number) using if(DaysOverdue > 0, mul(DaysOverdue, 5), 0). The parent loan-processing flow calls this once per overdue record.
Parent flowA flow that calls child flows using the "Run a child flow" action (Flow connector). Passes inputs to the child and reads outputs via dynamic content. Both must be in the same solution and environment."Process Book Return (Parent)" → calls "Calculate Late Fee (Child)" with DaysOverdue → reads LateFee output → calls "Send Return Confirmation (Child)" with LateFee → updates the loan row. The parent orchestrates; children execute reusable logic.
ConnectorA pre-built API wrapper connecting Power Platform to an external service. Standard connectors are free with M365 (SharePoint, Outlook, Teams). Premium connectors require a Developer Plan or per-user license (Dataverse direct, HTTP, SQL).The overdue-reminder flow uses the Outlook connector (Standard — free) to send emails. The "List rows" action uses the Dataverse connector (Premium — requires Developer Plan).
ConnectionOne authenticated instance of a connector — the specific "who" behind it. Connections are per-user. They are NOT stored in solutions (connection references are). Visible under Power Automate → My connections.Ashwini creates a Dataverse connection signed in as ashwini@learning.onmicrosoft.com. When the solution is imported to a new environment, she must create a new connection in that environment.
DLP (Data Loss Prevention)Admin policies controlling which connectors can be combined in a single flow. Categories: Business (can mix together), Non-Business (isolated), Blocked (cannot use). Applied at tenant or environment level.A DLP policy puts Outlook in Business group and blocks HTTP connector. The overdue-reminder flow (Dataverse + Outlook) is allowed. A flow trying Outlook + HTTP to an external URL is blocked at save time.
ApprovalA built-in "ask a human, then wait" step in Power Automate. Sends an approval request to a user or group via email/Teams, pauses the flow until they respond (Approve/Reject), then continues with their response and comments.A "New Member Approval" flow sends an approval request to the librarian when a new premium membership is requested. The flow waits — no timeout — until the librarian approves or rejects. The applicant gets an auto-email with the decision.
Adaptive CardAn interactive JSON panel with text, images, buttons — displayed inside Microsoft Teams. Flows can post Adaptive Cards to a Teams channel or send them to a specific user for in-Teams approvals or quick-response prompts.The overdue-reminder flow posts an Adaptive Card to the "Library Staff" Teams channel listing this week's overdue books — with member names, titles, and days overdue — so staff can act without leaving Teams.
SharePoint / listM365 team sites for document collaboration. SharePoint Lists are simple structured tables (like Dataverse-lite) — no security roles, no relationships, limited to 5,000 rows before performance degrades. Good for small, simple data.Before Dataverse, the library stored loans in a SharePoint list. After 200 rows the list became slow and the lack of relationships meant loan + member + book data had to be merged manually. Dataverse solved both problems.
Dataflow / Power Query / MDataflow = bulk import + transform tool in Power Platform. Power Query = its visual editor. M = its underlying functional language. Used to import CSV, Excel, SQL data into Dataverse on a schedule.Day 13: import the sample members.csv into cl_member using a Dataflow. Power Query lets you clean column names and cast data types before the rows land in Dataverse — no row-by-row manual entry.
Upsert / key columnAn import that updates existing rows instead of duplicating them. You designate a "key column" (e.g. cr_email) — if a row with that email already exists, it's updated; if not, a new row is created.Re-running the Dataflow with updated members.csv uses cr_email as the key column — Rohit Verma's membership type changes from Standard to Premium without creating a duplicate row.
API / REST / JSONAPI = a formal interface for programs to talk to each other. REST = the most common web API style (GET fetch, POST create, PATCH update, DELETE remove). JSON = the text format used for request/response data.The Dataverse OData REST API: GET https://org.crm8.dynamics.com/api/data/v9.2/cl_books?$filter=cr_available eq true returns a JSON array of available book rows.
Custom connectorA user-defined connector built from an OpenAPI spec — wraps any REST API so makers can use it in flows and apps like a built-in connector. Requires Premium license in production.If the library had an external ISBN-lookup API (api.openlibrary.org), you'd wrap it as a custom connector so a flow action called "Get Book by ISBN" appears in the maker portal — no raw HTTP needed.
Office ScriptA TypeScript automation that runs in Excel on the web, callable from Power Automate flows. Used when data is in Excel and you need to run a complex transformation or extract a value before processing further in the flow.A monthly stats script in Excel-on-web calculates aggregate loan counts per genre. A scheduled flow calls the Office Script, gets the result, and updates a Dataverse summary table — no need to open Excel manually.
Copilot StudioNo-code canvas for building AI chatbots and copilots. Topics define conversation paths; knowledge sources feed the AI for generative answers. Can call Power Automate flows to take actions.A "Library Assistant" chatbot in Teams answers "When is my book due?" by calling a flow that queries cl_loan filtered by the member's email. Members get answers without contacting staff.
Topic / knowledge sourceTopic = a scripted conversation path in Copilot Studio (trigger phrase → questions → actions → reply). Knowledge source = a SharePoint document or website the AI reads to answer unscripted questions generatively.Topic: "Check loan status" — trigger: "when is my book due?" → call flow → return due date. Knowledge source: the library's PDF policy document — members can ask "How do I extend a loan?" and get AI-generated answers.
Power BIMicrosoft's business intelligence tool — connects to data, transforms it (Power Query / M), builds a model (relationships, DAX measures), and publishes interactive reports. Used for data-driven decisions.The library's Power BI report shows: total loans this month, overdue rate by membership type, top 10 borrowed books, and member activity — all connected live to Dataverse.
Power BI DesktopFree Windows app for building Power BI reports. Full modelling, Power Query, and DAX editing. Reports are then published to the Power BI Service for sharing.Ashwini installs Power BI Desktop, connects to the Dataverse environment, and builds the library report locally. She publishes it to her Power BI workspace for the librarian to view in the browser.
Semantic model (dataset)The prepared, linked data a Power BI report reads from — includes tables, relationships, calculated columns, and DAX measures. The single source of truth for all visuals on all report pages.The library model has three tables: cl_book, cl_member, cl_loan, connected by relationships matching Dataverse. DAX measures (Total Loans, Overdue Rate) are defined once and used on multiple report pages.
DAX / measure / calculated columnDAX = Power BI's formula language. Measure = a dynamic calculation that re-evaluates with filters (e.g. Total Loans = COUNTROWS(Loan)). Calculated column = a per-row value stored at refresh time.Measure: Overdue Loans = CALCULATE(COUNTROWS(cl_loan), cl_loan[cl_status] = "Overdue"). Slicing by membership type automatically re-evaluates it — without any code change.
Filter contextThe set of active filters (from slicers, row context, cross-filtering, and CALCULATE) that a DAX measure evaluates under. Understanding filter context is the key to writing correct DAX.With the "Premium" membership slicer active, Total Loans evaluates only over loan rows joined to Premium members — the slicer creates the filter context automatically.
CALCULATEThe most powerful DAX function — evaluates any expression under a modified filter context. CALCULATE([Total Loans], cl_member[cr_membership_type] = "Premium") ignores the slicer and always shows Premium loans.Open Loans (Premium) = CALCULATE(COUNTROWS(cl_loan), cl_loan[cr_returned] = FALSE(), cl_member[cr_membership_type] = "Premium") — works correctly regardless of which slicer is active on the report.
Star schema (fact / dimension)Best-practice data model: a central "fact" table (measurements/events — Loans) surrounded by "dimension" tables (descriptive — Books, Members, Dates). Relationships radiate from fact to dimensions like a star.Library star schema: fact = cl_loan (LoanDate, LoanPeriod, LateFee), dimensions = cl_book, cl_member, Dates. All DAX measures are on the fact table; slicers come from dimension columns.
Row-level security (RLS)Showing different data to different Power BI viewers — enforced by a DAX filter on a role. The USERPRINCIPALNAME() function returns the viewer's email, used to filter rows to only their own data.RLS role "Member View" on cl_member: [cr_email] = USERPRINCIPALNAME(). Fatima logs into the Power BI Service and sees only her 5 loan rows — Rohit's 10 loans are invisible to her.
Date table / CALENDARAUTO()A special Dataverse or Power BI table with one row per day, plus Year/Month/Quarter columns. Required for time-intelligence DAX functions (TOTALYTD, SAMEPERIODLASTYEAR). CALENDARAUTO() generates it automatically.Add Dates = CALENDARAUTO() to the Power BI model, relate it to cl_loan[cr_loan_date]. Now TOTALYTD([Total Loans], Dates[Date]) gives a running YTD loan count that resets each January 1.
Import vs DirectQueryImport: copies data into Power BI — fast, scheduled refresh. DirectQuery: queries data live each time a visual loads — always fresh but slower. Choose Import for most scenarios; DirectQuery for real-time dashboards.The library report uses Import with a daily scheduled refresh — fast charts, up to 24 hours stale. A live-operations dashboard (who's in the library right now) would use DirectQuery for real-time accuracy.
Gateway (on-premises)Software on a local PC or server that lets Power BI Service refresh from local files or databases — bridging the cloud and on-premises. Not needed when data is already in Dataverse or SharePoint Online.If the library's loan history were in an on-premises SQL Server, an admin would install a gateway on the server's machine. Since it's in Dataverse (cloud), no gateway is needed — direct connection to the cloud.
GovernancePolicies, processes, and tools for keeping a Power Platform tenant safe, auditable, and manageable as usage grows. Covers: DLP policies, environment strategy, maker training, CoE Kit, audit logs, capacity management.Day 16: the library organisation adds a DLP policy to block HTTP in the DEV environment (prevents accidental data exfiltration by learners), and sets up the CoE Kit to track which apps are in use.
AzureMicrosoft's broader cloud platform — virtual machines, databases, AI services, DevOps, Key Vault, Entra ID. Power Platform is built on top of Azure; most integrations involve at least one Azure service.Day 16: create a Key Vault secret for a hypothetical API key. A Power Automate flow with the HTTP connector reads the secret at runtime — credentials never hard-coded in the flow definition.
Microsoft Entra IDMicrosoft's identity and access management service (was "Azure AD"). Manages users, groups, single sign-on, MFA, and OAuth 2.0 tokens. Every Power Platform login goes through Entra ID.When Rohit signs into the Library Member App, Entra ID validates his credentials and issues a token. The canvas app uses that token to query Dataverse — User().Email comes from the Entra ID token claim.
PL-900 / PL-300Microsoft certifications: PL-900 = Power Platform Fundamentals (foundational, multiple choice, entry-level). PL-300 = Power BI Data Analyst (hands-on, analytics-focused). Both available on learn.microsoft.com.After completing this 20-day course you have the hands-on skills to sit PL-900. The Power BI phase (Days 17–20) covers the core practical skills for PL-300.

When something goes wrong

ProblemTry this
"It signed me in as the wrong account."Close everything, open a fresh incognito window, sign in again with the learning account.
"I can't see my table / app / flow."Check the environment picker (top-right) shows your building environment. If you used the Developer Plan it is named after you — e.g. "Ashwini Pandey's Environment". If an admin created it, it is called "Learning". Everything lives per-environment — the wrong picker is the #1 cause of "missing" components.
"My flow didn't run."Open the flow's Run history. A red step shows exactly what failed. Click it to read the error message — it's almost always a missing required field or a wrong expression.
"Dynamic content I expected isn't showing."Dynamic content only shows outputs from steps above the current step. If a token is missing, check whether the step that produces it ran before the step that consumes it.
"The flow runs but the email body is blank."The variable or expression you used is empty. Check that Apply to each ran over a non-empty array, and that Append to string ran at least once before the email step.
"Expression error: 'invalid template language expression'."Expression syntax error. Common causes: unmatched parentheses, a function name mistyped, or a dynamic content token inside an Expression tab (use dynamic content in the dynamic content tab, expressions in the expression tab — not mixed).
"A formula has a red underline in Power Fx."Read the tooltip — usually a missing bracket/quote, a name typed wrong, or a column's logical name used instead of display name. Quotes must be straight " not curly ".
"Search() in canvas app returns no results."You must use the column's logical name (e.g. learn_title), not its display name. Find logical names in Dataverse → Tables → Columns → Column name field (not Display name).
"Form won't save — a required field is red."All Required columns must be filled. If the field is a Lookup (e.g. Book on Loan form), make sure DefaultSelectedItems is set correctly so it's pre-filled.
"Dataverse environment creation fails: needs 1GB capacity."Your tenant's Dataverse capacity is full. Use the Power Apps Developer Plan (powerapps.microsoft.com/developerplan) — permanently free, gives its own Dataverse environment with ~2GB.
"The chatbot won't answer from my document."Knowledge sources take 1–3 minutes to index after upload. Wait, then retry in the Test panel. If it still fails, check the file is text-based (not a scanned PDF image).
"Copilot Studio flow action isn't responding."The flow must use trigger type "Manually trigger a flow" with defined inputs. "Automated" or "Scheduled" triggers cannot be called by Copilot Studio. Check Run history in Power Automate.
"Azure is asking about payment / I'm worried about cost."Stop. Don't create virtual machines. Delete rg-learning immediately (Resource groups → rg-learning → Delete resource group). Do all Azure steps with the account owner present.
"DLP policy is blocking my flow."A DLP policy prevents combining the connectors in your flow. Check admin.powerplatform.microsoft.com → Policies → Data policies to see which policy applies and which connector is in the wrong group. If it's a test policy, delete it.
"A blue 'delegation' warning appeared in canvas app."Harmless for small practice data (under 500 rows). It means the filter/sort runs on the device, not the database. With thousands of rows this causes performance issues — use a delegable function or a filter on an indexed column.
"Power BI won't let me model / write DAX easily."The browser Service is limited; install free Power BI Desktop (Windows) for full modelling, Power Query, and DAX. All PL-300 exam skills assume Desktop.
"DAX measure shows blank / returns wrong number."Check that relationships exist (Model view). A measure reading Book[Genre] from the Loan table requires a Loan→Book relationship. Also check: are you on the right table? COUNTROWS(Loan) counts loan rows, not book rows.
"RLS 'Test as role' shows all rows — not filtered."The DAX expression in the role must reference a column that exists in the filtered table. Check the formula: [Email] = USERPRINCIPALNAME() — the column name must match exactly and the table must have an Email column with the user's UPN.
"My progress ticks disappeared."Ticks are saved in this browser on this device. A different device or clearing browser data resets them — that's expected. Re-tick as you revisit sections.
Tip — the single best habit When stuck, slow down and read the message on screen. Power Platform is unusually good at telling you what's wrong in plain-ish English. Nine times out of ten the fix is in the words you skipped. The second-best habit: check Run history in Power Automate and the expression error tooltip in Power Fx — both give exact, actionable error messages.
