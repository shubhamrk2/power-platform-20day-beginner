Phase 3 · Days 9–11

Automation

Make the computer do repetitive work by itself. You'll build three real flows wired into your Community Library: a loan confirmation email, an overdue-loans report that marks records, and a member approval process with Teams cards and full error handling.

Day 9

Your first flows: anatomy, triggers, actions, and run history

~110 minutes

Concept — what is a flow?

A flow is a recipe that runs itself: "When something happens, do these steps." The three moving parts:

  • Trigger — the "when." Exactly one per flow. Can be an event (a row is added), a schedule (every morning at 9), or a manual button press.
  • Actions — the "do this." Each action does one thing: send an email, update a row, post a Teams message, wait for an approval. You chain as many as you need.
  • Connectors — ready-made bridges to services. Dataverse, Outlook, Teams, SharePoint, Excel — hundreds of connectors exist. Each provides its own triggers and actions.
Concept — three ways a flow can start
  • Automated — starts on an event: a Dataverse row is added/changed, an email arrives, a file is uploaded. No human needs to do anything.
  • Instant (manual) — starts when you press a button in a canvas app or the "Run" button on the flow page.
  • Scheduled — starts on a timer: every day at 8am, every Monday. Good for overnight reports.
Concept — the flow designer: every element
  • Add an action — click the + button below any step, then search for a connector and action.
  • Dynamic content — when filling in an action's fields, click Dynamic content to insert tokens from earlier steps (e.g. Book title from the trigger).
  • Expression tab — next to Dynamic content, lets you type functions like utcNow().
  • Settings gear on each action — Timeout, Retry policy, Configure run after.
  • Parallel branch — run two sets of actions simultaneously.
  • Flow checker — the red badge icon at the top showing errors before you save.
Concept — trigger scope (Organization vs User)

The Dataverse trigger "When a row is added" requires a Scope:

  • Organization — fires for rows added by anyone in the environment. Use for system-wide automations like loan confirmations.
  • Business unit — only rows added by users in the same business unit as the flow owner.
  • User — only rows added by the flow owner themselves. For personal automation.

For the Community Library, always use Organization.

Do this — build the "Loan confirmation" flow
  • Solutions → My Learning Solution → New → Automation → Cloud flow → Automated. Name = Loan confirmation. Trigger = search When a row is added (Dataverse). Click Create.
  • Configure the trigger: Table name = Loan. Scope = Organization. Save.
  • Click + New step. Search Send me an email notification. Subject: type New Loan: then click Dynamic content → find Book (Value) from the trigger (the lookup display name, not the GUID).
  • Body: click Dynamic content → add Member (Value), type " has borrowed this book. Due: ", add Due date.
  • Save. Check Flow checker — 0 errors.
  • Test: open Library Manager → lend a book. Within 60 seconds check your inbox. Check Run history — click the run to see each action's inputs and outputs. This run history is your debug tool for every flow you ever write.
Tip — dynamic content for lookup fields Lookup columns appear twice in the dynamic content panel: an ID version (a long GUID) and a display name version (marked with "(Value)" or the FormattedValue suffix). For emails, always use the display name version.
Words you learned today
  • Flow — an automated "when… do…" recipe that runs by itself.
  • Trigger / action / connector — the "when" event / a "do" step / a bridge to a service.
  • Automated / instant / scheduled — event-triggered / button-triggered / timer-triggered.
  • Dynamic content — tokens from earlier steps you insert into an action's fields.
  • Run history — the log of every past run with full input/output details for debugging.
Real world — flows in enterprise automation

Power Automate runs over 50 billion actions per month across Microsoft's cloud. Real enterprise flows you'll find at companies:

  • A bank's loan application triggers a flow that sends confirmation to the customer (Outlook), creates a CRM record (Dataverse), and posts to a Teams channel for the review team — three parallel actions from one trigger.
  • A manufacturing company triggers a flow when a safety incident row is added to Dataverse — automatically notifying supervisors in under 30 seconds, no manual handoffs.
  • A logistics company runs a scheduled flow at 6am every day that reads delayed shipment rows, emails each customer individually, and updates a SharePoint list for customer service staff.

The Loan confirmation flow you just built is the same trigger → email action pattern used in every one of these examples. Scale is the only difference.

Common mistakes on Day 9
  • Using "Send an email (V2)" instead of Outlook connector without a licence. The full Outlook Send Email action requires an Exchange mailbox. "Send me an email notification" sends to the flow owner's address and works with any licence. Use the notification action while learning.
  • Wrong dynamic content for lookup display names. When you pick "Book" from the Dataverse trigger's dynamic content, you may get the GUID (a long code like 3e7b…). Always look for the version labelled "(Value)" or with the FormattedValue suffix — that's the human-readable name.
  • Building flows outside the solution. Always create flows via Solutions → My Learning Solution → New → Cloud flow. Flows created directly from the Power Automate portal aren't automatically tracked in the solution and can't be exported with it.

Mini-quiz — Day 9

Q1 You add a new Loan row and the confirmation email doesn't arrive within 2 minutes. What are the first two things you check?

Q2 What is the difference between "Scope: Organization" and "Scope: User" on a Dataverse trigger?

Q3 Dynamic content shows two versions for the "Book" column: one is a GUID and one says "Book (Value)". Which do you use in an email body, and why?

Show answers

A1 (1) Check the flow's Run history — is there a failed run? Click it to see which action failed and what the error message says. (2) Check that the flow is turned On — a flow that is off never runs.

A2 Scope Organization: the trigger fires for rows added by any user in the environment. Scope User: the trigger only fires for rows added by the flow's owner. For a shared library system, always use Organization.

A3 Use "Book (Value)" — that's the human-readable display name (e.g. "Matilda"). The GUID version (e.g. 3e7b1234-...) is the database ID, which is meaningless to an email recipient.

Day 10

Smarter flows: conditions, loops, variables, expressions, and parallel branches

~120 minutes

Concept — the four ideas that make flows intelligent
  • Condition — an "if / else" fork. The flow takes the Yes branch if true, the No branch if false.
  • Apply to each — a loop. Repeats steps for every item in an array (list).
  • Variable — a labelled box to hold a value while the flow runs. Initialize once (type + initial value), then Set or Append inside the loop.
  • Expression — a formula you type in the Expression tab to compute new values: format dates, add numbers, build strings.
Concept — essential expressions with exact examples
  • utcNow() — the current date/time in UTC.
  • formatDateTime(utcNow(), 'yyyy-MM-dd') — today's date as 2025-09-02.
  • addDays(triggerOutputs()?['body/learn_loandate'], 14) — add 14 days to Loan date (calculates Due date). Replace learn_loandate with your column's logical name.
  • length(outputs('List_rows')?['body/value']) — count how many rows List rows returned.
  • first(outputs('List_rows')?['body/value']) — get the first row from List rows.
  • items('Apply_to_each')?['cr_title@OData.Community.Display.V1.FormattedValue'] — display name of a lookup (Book Title) for the current loop item. Replace cr_title with your logical name.
  • items('Apply_to_each')?['learn_status@OData.Community.Display.V1.FormattedValue'] — label of a Choice column inside a loop (e.g. "Open", "Overdue").
  • concat('Book: ', items('Apply_to_each')?['cr_title@OData.Community.Display.V1.FormattedValue'], ' | Member: ', items('Apply_to_each')?['learn_member@OData.Community.Display.V1.FormattedValue']) — build a combined string.

You never memorize these — the Expression tab has a searchable function list. Type format to find date functions, items to find loop item functions.

Do this — build "Overdue check" with loop, condition, and parallel update
  • Solutions → My Learning Solution → New → Cloud flow → Instant. Name = Overdue check. Trigger = Manually trigger a flow. Create.
  • Add step: List rows (Dataverse). Table name = Loan. This fetches every loan row.
  • Add step: Initialize variable. Name = overdueList, Type = String, Value = (leave empty).
  • Add step: Apply to each. In "Select an output from previous steps": Dynamic content → value (from List rows — the array of all loan rows).
  • Inside Apply to each: add Condition. Left: Dynamic content → Returned from the loop item. Operator: is equal to. Right: Expression → false. Click + Add → AND. Second condition: Due date from loop item is less than Expression: utcNow().
  • In If yes: add Append to string variable. Name = overdueList. Value = Expression: concat(items('Apply_to_each')?['learn_book@OData.Community.Display.V1.FormattedValue'], ' / ', items('Apply_to_each')?['learn_member@OData.Community.Display.V1.FormattedValue'], ' · Due: ', items('Apply_to_each')?['learn_duedate'], decodeUriComponent('%0A')) — the last part adds a line break.
  • In If yes, add a parallel branch: click + → "Add a parallel branch." In the parallel branch add Update a row (Dataverse). Table = Loan. Row ID = Dynamic content → Loan (unique identifier). Fields: Status = Overdue. Now the flow both builds the report AND marks each loan in Dataverse simultaneously.
  • After the Apply to each (outside the loop): add Send me an email notification. Subject = Expression: concat('Overdue Loans — ', formatDateTime(utcNow(), 'yyyy-MM-dd')). Body = Dynamic content → overdueList variable.
  • Save → Test → Manually → Run. Check your inbox and check the Loan table — overdue loans should now show Status = Overdue.
  • Convert to scheduled: edit the trigger → change to Recurrence. Interval = 1, Frequency = Day, Start time at 08:00. Save. The flow now runs automatically every morning.
Tip — "OData.Community.Display.V1.FormattedValue" explained When Dataverse returns rows, lookup columns come as GUIDs (useless) and Choice columns come as integers. Microsoft adds this long suffix to also give you the human-readable version. If you see Book@OData.Community.Display.V1.FormattedValue in the dynamic content panel, that's "the Book's Title as a readable string." Always use the FormattedValue version in emails and variables.
Words you learned today
  • Condition — an if/yes/no fork in the flow.
  • Apply to each — a loop that runs inner steps for every item in an array.
  • Variable / Initialize / Append — a named value box / create it with a type / add text to it.
  • Expression — a typed function that computes a new value (dates, strings, counts, arrays).
  • Parallel branch — two sets of actions that run simultaneously.
  • Recurrence trigger — starts a flow on a timer (daily, weekly, monthly).
Real world — loops, conditions, and variables in enterprise flows

The Apply to each + Condition + Variable pattern you built today is the backbone of all report-generation flows in real companies:

  • A bank's end-of-day flow loops through all flagged transactions, checks each one's amount, and builds a report string of transactions over the limit — exactly like your overdue list string.
  • A supply chain company's flow runs each morning: Loop through open Purchase Orders → if delivery is overdue → append to delay string → mark PO as Delayed → after loop, email the procurement team. Same exact structure as your Overdue check flow.
  • The parallel branch pattern (update the record AND build the string simultaneously) saves time in high-volume flows — instead of 1000 sequential steps, two parallel branches finish in half the time.
Common mistakes with loops and variables
  • Placing Initialize variable inside Apply to each. A variable must be initialized BEFORE the loop (outside Apply to each). If you initialize inside, it resets to blank on every iteration — your accumulated string becomes empty each loop.
  • Using the wrong "value" in Apply to each. When you configure Apply to each, you must select the value output from the List rows action — this is the array of rows. If you accidentally select something else, the loop body doesn't have the individual row columns available.
  • Forgetting the OData FormattedValue suffix for display names in loops. Inside Apply to each, lookup and choice columns need the @OData.Community.Display.V1.FormattedValue suffix to get human-readable text. The exact logical name + suffix appears in the Expression tab's dynamic content when you're inside the loop.

Mini-quiz — Day 10

Q1 Where must you place the "Initialize variable" action relative to an Apply to each loop?

Q2 You have a flow that loops through 500 rows and takes 10 minutes. A colleague suggests adding a parallel branch inside the loop. Will this make it faster?

Q3 What does formatDateTime(utcNow(), 'yyyy-MM-dd') return, and when would you use it?

Show answers

A1 Before (outside) the Apply to each loop. If placed inside, it resets to its initial value at the start of every iteration — losing all accumulated data from previous iterations.

A2 Yes — parallel branches inside a loop run simultaneously. If each iteration previously took 1 second for two sequential actions, adding a parallel branch for those two actions can halve the per-iteration time. However, Power Automate has throttling limits per connector — very high volumes may still be slow due to API limits.

A3 It returns today's date as a string like 2025-09-15. Use it in email subjects, filenames, or as the date portion of a log entry — any place where you need today's date formatted as readable text rather than an ISO timestamp.

Day 11

Approvals, Adaptive Cards, data operations, and error handling

~130 minutes

Concept — approvals: asking a human and waiting

An approval is a built-in action that sends a request to one or more people and pauses the flow until they respond. Types:

  • Approve/Reject — First to respond — any one approver clicking is enough to continue.
  • Approve/Reject — Everyone must approve — all assigned approvers must approve; one Reject rejects the whole thing.
  • Custom responses — define your own options ("Approve / Reject / Request more info").

Approvals appear in three places: the Approvals app in Teams, the approver's Outlook email (with clickable buttons), and the Power Automate Approvals page.

Concept — Adaptive Cards

An Adaptive Card is a richly formatted interactive panel that appears inside Teams. The approver sees the details and Approve/Reject buttons directly in Teams — no need to open an email or a web page. It's described in JSON (structured text). Power Automate has a "Post adaptive card and wait for a response" action that handles the JSON for you, but you can also write custom JSON.

Concept — data operations: Compose, Select, Filter array, Join
  • Compose — store any value in a named token for later reference. Avoids repeating a complex expression.
  • Select — reshape an array of rows: pick specific columns, rename them. Produces a cleaner array for downstream actions.
  • Filter array — filter an array of objects by a condition. More efficient than Apply to each + Condition for simple filters on small arrays.
  • Join — turn an array into a single string. E.g. ["Matilda","Dune"] → "Matilda, Dune".
Concept — Try/Catch: error handling

Wrap main work in a Scope named "Try". Add another Scope named "Catch" set to run only when Try has failed (via Configure run after). Inside Catch, send an email or log the error details.

  • Add step → Scope → rename Try. Drag your main actions inside.
  • After Try, add another Scope → rename Catch. Click its Settings gear → Configure run after → tick "has failed", untick "is successful".
  • Inside Catch: add Send email. Body = Expression: string(result('Try')) — gives a full JSON summary of what failed and why.

Words you learned today
  • Approval / outcome — a "pause and ask a human" step / the Approve/Reject/custom answer.
  • Adaptive Card / JSON — an interactive Teams panel with buttons and inputs / the structured text that describes it.
  • CRUD — Create, Read, Update, Delete — the four data operations.
  • Data operations — Compose / Select / Filter array / Join — built-in tools for working with arrays.
  • Try/Catch scope — a Try scope containing the main work, a Catch scope that runs only on failure.
  • result('ScopeName') — expression returning the output/error of a scope, used in Catch for diagnostics.
Real world — approvals and error handling in enterprise

Approval flows are one of the highest-value Power Automate features in enterprise:

  • A multinational uses approval flows for expense reports: when a manager's expense exceeds ₹50,000, the flow pauses and waits for the CFO's approval — which they give from their phone in the Teams Approvals app, without opening a separate system.
  • A healthcare provider's new patient onboarding flow waits for the records team to verify ID — the flow has been running (paused, waiting) for up to 30 days. Power Automate supports long-running paused flows.
  • Try/Catch scopes are standard practice in production: without them, a failed action silently kills the flow. With Catch, you always know what broke and can alert the right person. The expression string(result('Try')) is copy-pasted across thousands of enterprise flows worldwide.
Common mistakes with approvals and error handling
  • Using "First to respond" when all approvers must agree. If you have 3 approvers and use "First to respond", the first person to click Approve ends the approval — even if the other two would have rejected. Use "Everyone must approve" when consensus is required.
  • Not checking the Outcome before branching. The Approval action outputs "Approve" or "Reject" (exact strings, case-sensitive). If your Condition checks for "approve" (lowercase), it will never match. Always check by clicking the run and reading the exact Outcome string in Run history.
  • Putting the Catch scope inside the Try scope. Catch must be AFTER Try (outside it), not inside. An inner scope doesn't have access to the Try scope's result. Configure run after → has failed on the Catch scope.
  • Forgetting to set "run after" on the Catch scope. Without configuring "has failed", the Catch scope runs after every run (success AND failure). Always click the Catch scope's Settings → Configure run after → tick "has failed", untick "is successful".

Mini-quiz — Day 11

Q1 A flow has a Try scope and a Catch scope. Under what condition does the Catch scope run?

Q2 An approval flow uses "Approve/Reject — Everyone must approve" with 3 approvers. Two approve, one rejects. What is the Outcome?

Q3 You receive a blank error email from the Catch scope. What does this tell you, and what should you check?

Show answers

A1 Only when the Try scope has a failed status — because you configured the Catch scope's "run after" setting to "has failed" only. If Try succeeds, Catch is skipped.

A2 Reject — with "Everyone must approve", a single Reject from any approver rejects the entire approval. The flow takes the "If no" branch.

A3 A blank error email usually means result('Try') returned empty — possibly because the Try scope name was changed or misspelled in the expression. Check that the Catch scope's expression exactly says string(result('Try')) where 'Try' matches the exact name of the Try scope (case-sensitive, spaces replaced with underscores).
