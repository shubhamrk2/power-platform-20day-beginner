Phase 3 · Days 9–11

Automation

Make the computer do repetitive work by itself. You'll build flows that react to events, add logic, ask a human to approve, post interactive cards to Teams, and change data safely.

Day 9

Automation begins: your first flow

~100 minutes

Concept — what is a "flow"?

A flow is a little recipe that runs by itself: "when something happens, do these steps." For example: when a new book is added, send me an email. The two building blocks are a trigger (the "when" — exactly one per flow) and one or more actions (the "do this"). Steps reach services through connectors — ready-made bridges to Outlook, Teams, Dataverse, and hundreds more.

Concept — three ways a flow can start
  • Instant — you press a button to start it.
  • Automated — it starts on an event (a row added, an email arrives).
  • Scheduled — it starts on a timer (every morning at 9).
Do this — build two simple flows
  • Go to make.powerautomate.com; confirm the environment is Learning.
  • Create → Instant cloud flow, trigger Manually trigger a flow; add Send me an email notification. Save → Test → Manually → Run. Check your inbox.
  • Create → Automated cloud flow, trigger When a row is added (Dataverse) → table Book → action Send me an email notification.
  • Add a Book; within a minute the flow emails you. Open Run history to see the green ticks.
Tip — "dynamic content" is data from earlier steps When filling an action, insert dynamic content — tokens like Book Title that carry a value from the trigger. That's how the email can say which book was added.
Words you learned today
  • Flow — an automated "when… do…" recipe.
  • Trigger / action / connector — the "when" / a "do" step / a bridge to a service.
  • Instant / Automated / Scheduled — the three ways a flow can start.
  • Run history — the log of past runs (to see success or errors).
Check yourself Adding a book now emails you automatically. If not, Run history tells you which step needs attention.
Day 10

Smarter flows: conditions, loops, variables, expressions

~110 minutes

Concept — the four ideas behind every automation
  • Condition — an "if / else" fork.
  • Apply to each — a loop: repeat steps for every item in a list.
  • Variable — a labelled box to store/update a value while the flow runs (Initialize then Set/Append).
  • Expression — a small function you type, e.g. formatDateTime(...) or concat(a,b).
Do this — a flow that thinks
  • Instant flow → add List rows (Dataverse) → table Book (fetches all books).
  • Initialize variable bigBooks (String, empty).
  • Apply to each over the rows; inside, a Condition: Pages > 300.
  • In "If yes", Append to string variable the book's Title + a comma.
  • After the loop, email yourself the bigBooks variable. Test. Change 300 to 100 and re-test.
Tip — you don't memorise expressions Click into a field and the Expression tab shows a searchable list of functions with descriptions. Start typing (e.g. format) to find what you need. Learn by browsing.
Words you learned today
  • Condition / Apply to each — an if/else branch / a loop over a list.
  • Variable — a value the flow stores and updates.
  • Expression / dynamic content — a typed function / values from earlier steps.
Check yourself Your flow emails a list of books over 300 pages, and you proved you understand the condition by changing the number.
Day 11

People, cards, data changes & error handling

~120 minutes · this day covers several tightly-linked topics

Concept — approvals and Adaptive Cards

Often an automation needs a human to say "yes". Power Automate's approval action sends a request and waits for Approve/Reject, then continues based on the answer. An Adaptive Card is a small interactive panel — text plus buttons — that appears inside a Microsoft Teams chat, so you can capture a decision right there. (A card is described in JSON, but a flow action builds it for you.)

Concept — changing data (CRUD) and handling failures

Flows can change your database too. The four operations are CRUD: Create, Read, Update, Delete — Dataverse has an action for each. And because steps sometimes fail (a service is down, a value is missing), you add error handling: each action's "Configure run after" can make a step run only if the previous one failed. Grouping steps in a Scope and adding a "run after failure" scope gives a simple try/catch.

Do this — approval, Teams card, and a safe data-change flow
  • Automated flow, trigger When a row is added (Book) → Start and wait for an approval (Approve/Reject, assigned to yourself).
  • Add a Condition on Outcome = Approve; email "Approved" vs "Rejected" in each branch. Add a book and approve it from the email or the Approvals page.
  • Teams card: a new flow with Post adaptive card and wait for a response (Teams) → post to yourself → sample Approve/Reject card → capture the response.
  • Data change + errors: instant flow with text inputs → Add a new row (Book) → Update a row (set In stock = Yes). Wrap actions in a Scope "Try"; add a Scope "Catch" set to run after has failed, emailing you the error.
Tip — break it on purpose Temporarily leave a required field blank, run the flow, and watch the Catch scope email you. Then fix it. Deliberately (safely) breaking things is one of the fastest ways to learn.
Words you learned today
  • Approval / outcome — an "ask a human and wait" step / their answer you branch on.
  • Adaptive Card / JSON — an interactive Teams panel / the structured text describing it.
  • CRUD — Create, Read, Update, Delete.
  • Scope / Configure run after — a group of actions / control whether a step runs on failure.
Check yourself Adding a book triggers an approval and branches on the answer; you posted a Teams card; and you built a flow that changes data and emails you if a step fails. That's the shape of most real automations.
