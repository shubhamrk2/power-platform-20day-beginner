Phase 5 · Days 15–16

AI & governance

Build an AI chatbot with Copilot Studio, then learn how organisations keep a growing platform safe and tidy — governance, DLP, and moving solutions from build to live — plus a first, cost-safe look at Azure.

Day 15

AI you can build: Copilot Studio chatbots

~110 minutes

Concept — what is a Copilot Studio "agent"?

Copilot Studio lets you build a chatbot (now often called an agent) — a helper people chat with. You give it a personality, some knowledge to answer from, and optional "skills" (actions it can take, like looking something up in your data).

Concept — the building blocks
  • Instructions — the agent's personality and rules (its "job description").
  • Topics — set conversation paths triggered by phrases (e.g. "opening hours").
  • Knowledge sources — documents/sites it reads to answer questions ("generative answers").
  • Actions — things it can do by calling a flow.
  • Channels — where it's published (a website, Teams…).
Do this — build and publish a simple chatbot
  • copilotstudio.microsoft.com (Learning environment); start the trial if asked. Create → New agent = Library Helper.
  • Set Instructions: "You are a friendly library assistant. Answer questions about books politely and briefly."
  • Add a Knowledge source: upload a one-page FAQ you write (opening hours, how to borrow — made up).
  • Create a Topic with trigger phrases like "opening hours" + a message answer.
  • Use the Test panel to chat with it (wait a minute if knowledge is still indexing). Then Publish → Demo website and chat with it in a normal tab.
Tip — topics vs generative answers A topic is a scripted path you control exactly. Generative answers let the AI answer freely from your knowledge when no topic matches. Good agents use both.
Words you learned today
  • Agent / chatbot — a helper people chat with.
  • Instructions / topic / trigger phrase — its rules / a scripted path / the words that start it.
  • Knowledge source / action / channel — what it answers from / what it can do / where it's published.
Check yourself A published chatbot that answers from your FAQ and a scripted topic. You're now building with AI. 🤖
Day 16

Governance, DLP, ALM — and a first look at Azure

~120 minutes · this day covers governance and a short Azure tour

Concept — governance and DLP

When hundreds of people build across a company, you need rules and oversight so nothing leaks or breaks — that's governance, managed in the Power Platform admin center. A key tool is DLP (Data Loss Prevention): a rule about which connectors may be used together. Connectors sit in groups — Business, Non-business, Blocked — and a flow can't mix Business with Non-business, so company data can't be wired straight to a personal service.

Concept — ALM (build → test → live)

ALM (Application Lifecycle Management) means building in one environment (Dev), testing in another (Test), and running for real in a third (Production) — moving your solution (the "box" from Day 4) between them safely.

Do this — look, export, and take a tiny Azure tour
  • admin.powerplatform.microsoft.com: tour Environments and Resources → Capacity. Open Policies → Data policies and look at how connectors drag between Business / Non-business / Blocked.
  • make.powerapps.com → Solutions → My Learning Solution → Export → Unmanaged → download the .zip. That zip is your whole solution as a movable file.
  • Azure tour (with the account owner): open portal.azure.com; read the home page; create a Resource group rg-learning (a free "folder").
  • Create a Key Vault in it (a safe for secrets); add a made-up secret DemoSecret = not-a-real-password. Look at Microsoft Entra ID → Users (the identity system).
  • Clean up: Resource groups → rg-learning → Delete resource group (type the name). This removes everything so nothing bills.
Careful — the Azure rule Do the Azure part with the account owner, never create a "virtual machine", and always delete rg-learning at the end. Azure can bill by the hour; the rest of this course cannot.
Words you learned today
  • Governance / admin center — rules & oversight / where admins manage them.
  • DLP — rules about which connectors can be combined (Business/Non-business/Blocked).
  • ALM / managed / unmanaged — Dev→Test→Prod / locked (shipped) vs editable solution.
  • Azure / resource group / Key Vault / Entra ID — Microsoft's big cloud / a folder of resources / a safe for secrets / the identity system.
Check yourself You can explain DLP and Dev/Test/Prod simply, you exported a portable solution, and you created — then deleted — Azure resources. Cleaning up is as important as creating. ✅
