Phase 5 · Days 15–16

AI & governance

Build a Library Helper chatbot in Copilot Studio — with scripted topics, knowledge-based answers, and a live Dataverse lookup — then learn how organisations keep Power Platform safe: DLP policies, Application Lifecycle Management (Dev → Test → Production), and a cost-safe Azure tour covering Key Vault, Entra ID, and Logic Apps.

Day 15

Copilot Studio: building a real library chatbot

~130 minutes

Concept — what is Copilot Studio?

Copilot Studio is Microsoft's low-code platform for building agents (chatbots that can converse, look things up, and take actions). You can build one without writing code. The major building blocks:

  • Instructions — a plain-English "job description" for the agent: its personality, tone, and scope rules.
  • Topics — scripted conversation paths that activate when a user says certain phrases. You control the exact flow: ask a question, branch on the answer, send a message.
  • Knowledge sources — documents, SharePoint pages, or websites the AI reads to answer questions outside of scripted topics. Called generative answers.
  • Actions — things the agent can do by calling a Power Automate flow or Dataverse query. This is how it looks up live data.
  • Variables — values the agent stores during a conversation (e.g. what book the user asked about). Types: text, number, boolean, table.
  • Entities — things Copilot Studio recognises automatically (dates, numbers, email addresses, currencies) or that you train (e.g. a list of book genres).
  • Channels — where the agent is published: Teams, a demo website, a canvas app widget, or a website via embed code.
Concept — topics vs generative answers

These two modes work together:

  • Topic — scripted. You define the exact phrases that trigger it and the exact messages/questions the bot sends. Perfect when you need predictability (compliance, safety, brand).
  • Generative answers — AI-powered. When no topic matches, the agent searches your knowledge sources and generates a natural answer. Adds a lot of capability with minimal authoring effort.

Good agents use both: scripted topics for key workflows, generative answers as a safety net for everything else.

Do this — build Library Helper step by step
  • Go to copilotstudio.microsoft.com. Confirm environment = Learning (top right). Start the Copilot Studio trial if prompted. Create → New agent. Name = Library Helper. Click Create.
  • Set Instructions: "You are a friendly and brief assistant for the Community Library. Answer questions about opening hours, borrowing, and book availability. If a question is off-topic, politely redirect to library topics. Do not make up information."
  • Knowledge source — FAQ document: create a text file called library-faq.txt with content like:
    "Opening hours: Mon-Sat 9am-7pm, Sun 11am-5pm. Standard loan period: 14 days. Students: free membership. Late fee: ₹5 per day overdue. How to borrow: visit any librarian with your membership card."
    In Copilot Studio → Knowledge → + Add → Upload a file → upload library-faq.txt. Wait ~1 minute for indexing.
  • Topic 1 — Opening hours: Topics → + New topic → From blank. Name = Opening hours. In trigger phrases: add 3 variations: when are you open, opening hours, what time do you close. Add a Message node: "We're open Mon–Sat 9am–7pm and Sunday 11am–5pm. Is there anything else I can help you with?" Save topic.
  • Topic 2 — How to borrow: + New topic → From blank. Name = How to borrow. Triggers: how do I borrow, borrow a book, checkout. Message: "To borrow a book: bring your membership card to any librarian. Standard loan period is 14 days. Need to check if a book is available first?" Add a Question node: "Which book are you looking for?" Save the answer to a variable — name it BookTitle (type = text). Save topic.
  • Topic 3 — Book availability (with live Dataverse lookup):
    First, build the Power Automate flow: make.powerautomate.com → Solutions → My Learning Solution → New → Cloud flow → Instant. Trigger = Manually trigger a flow. Add an input: BookTitle (text).
    Add List rows (Dataverse). Table = Book. Filter rows = contains(learn_title, '@{triggerBody()?['text']}'). Top count = 1.
    Add Condition: Expression: length(outputs('List_rows')?['body/value']) is greater than 0.
    If yes: add Respond to a Power Apps or flow action → Output name: Result, value = Expression: concat(first(outputs('List_rows')?['body/value'])?['learn_title'], ' is available. Copies: ', string(first(outputs('List_rows')?['body/value'])?['learn_availablecopies'])).
    If no: Respond to a Power Apps or flow → Result = Expression: concat(triggerBody()?['text'], ' was not found in our catalogue.').
    Save the flow as Library - Check book availability.
  • Back in Copilot Studio → + New topic. Name = Book availability. Triggers: is X available, do you have, check book. Add a Question node: "Which book would you like to check?" Variable = BookTitle.
    Add Action → Run a flow → find Library - Check book availability. Map input BookTitle → variable BookTitle. Output variable = AvailabilityResult.
    Add a Message node: text = variable AvailabilityResult. Save.
  • Test: click Test your agent (right panel). Type when are you open — verify the scripted response. Type what is the late fee — verify generative answer from the FAQ. Type is Dune available — verify the flow runs and returns a result. If the flow doesn't respond, check Run history in Power Automate.
  • Publish: click Publish → Publish. Then Channels → Demo website → Copy the link → open in a new tab → chat with your bot as a real user would.
Tip — variable scope in topics Variables defined in a topic are topic-scoped by default — they exist only within that conversation branch. To pass a value between topics, change the variable type to Global in its properties. The bot's overall session state lives in Global variables.
Words you learned today
  • Agent / chatbot — an AI-powered conversational helper people type questions to.
  • Instructions — the plain-English rules and personality the agent follows.
  • Topic / trigger phrases — a scripted conversation path / the words that activate it.
  • Knowledge source / generative answers — content the AI reads to answer free-form questions.
  • Action — a Power Automate flow the agent can call to look up or change data.
  • Variable — a named value stored during the conversation (text, number, boolean, table).
  • Entity — something Copilot Studio recognises automatically (date, email, custom list).
  • Channel / demo website — where the agent is published / a shareable test URL.
Check yourself Library Helper answers scripted questions, generates answers from the FAQ, AND looks up real Dataverse book data. That's the full Copilot Studio stack: scripted + generative + live data. If the availability check didn't work, recheck the flow trigger type (it must be "Manually trigger a flow" with a text input) and the Run history.
Day 16

Governance, DLP, ALM, analytics — and a cost-safe Azure tour

~130 minutes

Concept — governance: why it matters

When thousands of employees build flows and apps across an organisation, you need:

  • Rules about what they can connect to (DLP).
  • Visibility into what's been built (analytics and inventory).
  • A safe process to move tested solutions to production (ALM).
  • Identity and access controls (Entra ID / security roles).

All of this is managed in the Power Platform admin center (admin.powerplatform.microsoft.com). An admin governs; makers build. The same admin center is where you approved environments and checked capacity.

Concept — DLP policies in detail

A Data Loss Prevention (DLP) policy controls which connectors can be used together in a single flow or app. Every connector is placed in one of three buckets:

  • Business — trusted, company-approved connectors. Dataverse, SharePoint, Teams, Outlook, Azure AD. Flows can freely combine connectors within this group.
  • Non-business — personal or consumer connectors. Twitter/X, Dropbox, personal Gmail, Instagram. A flow cannot combine a Business connector with a Non-business connector — this stops someone wiring Dataverse → Twitter.
  • Blocked — completely disallowed in the environment. Any flow that tries to use a blocked connector won't run.

A policy can apply to all environments, selected environments, or be an environment-admin policy scoped to just one. For your Learning environment, you're both maker and admin, so you can create and delete test policies freely.

Concept — ALM: Dev → Test → Production

Application Lifecycle Management (ALM) is the practice of keeping different stages of a solution separate:

  • Dev environment — where makers build and experiment freely. Your Learning environment has been Dev.
  • Test environment — where the solution is imported as managed and tested by users. Makers can't edit managed components directly.
  • Production environment — where live users run the real system. Only managed solutions are deployed here.

The movement: export managed from Dev → import into Test → test → import same managed solution into Production. Connection references let each environment's connections (e.g. which Dataverse environment the flows point to) differ without changing the solution itself.

Concept — Power Platform analytics

The admin center's Analytics section shows usage data across the tenant:

  • Power Apps analytics — which apps were launched, by whom, from which environment, on what device.
  • Power Automate analytics — flow run counts, error rates, which connectors are used most.
  • Dataverse analytics — API call counts, storage consumption, active users.

This data helps admins identify unused solutions to clean up, popular flows to protect, and environments that are consuming too much capacity.

Concept — Azure: the cloud behind the cloud

Azure is Microsoft's cloud platform of infrastructure and platform services. Power Platform sits on top of Azure — so knowing Azure's basics helps you understand the foundations. Key services:

  • Resource group — a logical folder that holds related Azure resources. Billing and permissions roll up to the group. Delete the group → everything inside is deleted.
  • Key Vault — a safe for secrets (API keys, passwords, certificates). Power Platform can reference Key Vault secrets so credentials aren't hardcoded anywhere.
  • Microsoft Entra ID (formerly Azure AD) — the identity system. Every Microsoft 365 and Azure user is an Entra ID user. This is where you manage users, groups, and app registrations (OAuth apps).
  • Logic Apps — Azure's own flow-builder, similar to Power Automate but deployed and managed as an Azure resource. Used by IT teams who need advanced network isolation or enterprise SLA guarantees. Power Automate and Logic Apps share many connectors.
  • Azure DevOps — source control (Git repos), pipelines (CI/CD), and work item tracking for enterprise teams. Power Platform pipelines (for ALM) can integrate with Azure DevOps for automated deployments.
Do this — DLP tour, export managed solution, Azure walkthrough
  • Admin center tour: admin.powerplatform.microsoft.com → Environments → click your Learning environment → view the Resources panel (apps, flows). Go to Analytics → Power Apps and read the usage charts.
  • Create a test DLP policy: admin center → Policies → Data policies → + New policy. Name = Test policy — delete me. Scope = this environment only. Find Twitter connector → drag it to Blocked. Find Dataverse → confirm it's in Business. Next → Create policy.
  • Try to create a flow that uses both Dataverse and Twitter — verify it's blocked by the policy. Then delete the test policy: Policies → Data policies → select the policy → Delete. (Real environments have permanent policies — you just learned how they work.)
  • Export managed solution: make.powerapps.com → Solutions → My Learning Solution → Export solution. Version = 1.0.0.1. Select Managed. Export. Download the zip — this is what you'd deploy to Test/Production. It's locked: nobody can edit the components inside after import.
  • Also export Unmanaged — save both zips. The unmanaged zip is your development backup. Keep both permanently: they are your entire project in two files.
  • Back up your data: open Loan table → Export → Export to Excel. Do the same for Member. These files keep your rows; the solution zips keep the schema and logic.
  • Azure tour (do this with the account owner — read the warning card first):
    Open portal.azure.com. Sign in with the same learning account (it's the same Microsoft account). Read the home page: note the top menu (All resources, Resource groups, Marketplace, Cost Management).
    Click Resource groups → + Create. Subscription = (the trial or free tier). Region = any near you. Name = rg-learning. Click Review + create → Create. A resource group costs nothing — it's a free folder.
    Inside rg-learning: click + Create → search "Key Vault". Click Key Vault → Create. Name = kv-library-learning (must be globally unique — add random digits if needed). Region = same as resource group. Pricing tier = Standard. Review + create → Create. Wait ~1 minute.
    Open the Key Vault → Secrets → + Generate/Import. Upload options = Manual. Name = DemoSecret. Secret value = not-a-real-password. Create.
    Now browse: portal home → Microsoft Entra ID (in the left menu or search). Click Users → All users — every M365 user appears here. This is the identity backbone of every Microsoft cloud service.
    Search "Logic Apps" in the portal — click it, read the overview page. Note how similar it is to Power Automate: triggers, actions, connectors. This is the enterprise-grade version used by IT teams.
    Briefly note: Azure DevOps (dev.azure.com) — where enterprise teams store Git repos and run CI/CD pipelines that can deploy Power Platform solutions automatically.
CRITICAL — always delete rg-learning before leaving Azure Azure charges by the hour for many services. Some services start free but accrue cost after a period. The safe exit is always: Resource groups → rg-learning → Delete resource group (type rg-learning to confirm). This deletes the Key Vault and everything else inside. Do this before you close the Azure portal. Never create Virtual Machines (VMs) in this learning tour. Never leave Azure without deleting rg-learning.
Words you learned today
  • Governance / admin center — rules and oversight for the platform / the portal where admins manage them.
  • DLP / Business / Non-business / Blocked — connector-combination rules / the three groups connectors live in.
  • ALM / Dev / Test / Production — the practice of staged solution deployment / the three standard environments.
  • Managed solution — a locked, deployable package; makers cannot edit its components after import.
  • Connection reference — a pointer in a solution that tells each environment which connection to use.
  • Analytics — usage dashboards in the admin center (who runs what, how often, with what errors).
  • Azure / resource group / Key Vault / Entra ID / Logic Apps — Microsoft's cloud / a billing folder / a secrets safe / the identity system / the enterprise flow-builder.
